> Tsumigeya の画面は簡体字中国語・英語・日本語に対応しており（設定 → 言語）、既定ではシステム言語に従います。本書では画面内の項目名を原文である簡体字中国語で「」に引用し、初出時に日本語名を添えています。英語版の画面では同じ項目が英語で表示されます。

## インストールと更新

### 対応している Mac は？

現在のインストーラは **macOS 26 以降と Apple Silicon** が必要です。Intel 用インストーラは提供しておらず、Windows や Linux のネイティブ版もありません。

<a id="first-launch"></a>

### 初回起動で「開発元を確認できません」または「アプリが壊れています」と表示されたら？

まず、インストーラが出所不明の転載ではなく、このリポジトリの Releases から取得したものか確認してください。現在のアプリは ad-hoc 署名のみで、Developer ID の配布用署名はなく、Apple の公証も受けていないため、Gatekeeper にブロックされることがあります。

入手元を信頼できる場合は、すでにアプリケーション（「应用程序」）に入れたアプリに対して次を実行できます:

```bash
xattr -dr com.apple.quarantine /Applications/Tsumigeya.app
```

これはそのアプリのダウンロード隔離フラグを外すだけで、公証や安全性の証明ではありません。**システム全体のセキュリティ保護を無効にしないでください。** それでも警告が出る場合は、すべての問題を隔離フラグのせいにせず、インストーラを再ダウンロードしてダウンロードが完全かどうかを確認してください。

リリースの添付にある `SHA256SUMS.txt` にインストーラのチェックサムが記録されています。ダウンロードフォルダでインストーラの SHA-256 を確認し、そのバージョンのチェックサムファイルと項目ごとに比較できます:

```bash
shasum -a 256 Tsumigeya-*.dmg
```

アプリを `/Applications` 以外にインストールした場合、コマンド内のパスもそれに合わせて変更する必要があります。

### 更新方法は？ゲームライブラリは失われますか？

Tsumigeya を終了し、新しい DMG をダウンロードして、アプリケーション内の古いアプリを置き換えます。アプリのデータは `.app` とは別に保存され、現在のバージョンは次のディレクトリを使用します:

```text
~/Library/Application Support/Tsumigeya/
```

更新前にはアプリデータと実際のゲームのセーブデータをバックアップすることをおすすめします。過去のバージョンからの移行説明は該当する Release に従ってください。「古いバージョンを整理する」ためにアプリデータディレクトリを削除しないでください。

## ゲームとランタイム

### 任意の Windows ゲームを動かせますか？

任意の Windows ゲームを保証することはできません。Tsumigeya は Wine 経由で確認済みの Windows `.exe` を起動しますが、ドライバ、アンチチート、DRM、特殊なグラフィックスインターフェース、追加の依存関係などが原因で互換性がない場合があります。Unity、RPG Developer Bakin、WOLF RPG Editor の古い記録は Wine 経由で読み込まれ、認識のみ（「仅识别」）として個別に表示されることはなくなりました。

エンジンを認識できても互換性が保証されるわけではありません。プラグイン、スクリプト拡張、暗号化方式、依存関係が結果に影響します。具体的な範囲は[ゲームの互換性](../../README.ja.md#compatibility)を参照してください。

### Wine はどう使いますか？

エンジン管理（「引擎管理」）ページで Windows 互換の Wine（「Wine（Windows 兼容）」）をインストールし、完全に解凍したゲームを追加します。Windows ゲームはフォルダ内の説明ファイルなどの通常のファイルを選んで認識させることもできます。EXE が 1 つだけなら自動で入力され、複数ある場合はインストーラやアンインストーラではなく実際の起動ファイルを確認する必要があります。専用の macOS ランタイムがあるゲームは、引き続き既存のランタイムが優先されます。

ゲーム編集（「编辑游戏」）では Windows の起動ファイル、行ごとの起動引数、中／日／英のロケールを調整できます。「エンジン管理 → Windows 環境設定…」（「引擎管理 → Windows 环境设置…」）では Windows のバージョン、オーディオ、DLL などを調整できます。初回起動では環境の初期化が必要なため、2 回目以降より時間がかかります。Apple シリコンの Mac で Rosetta 2 がない場合は、先に Apple のライセンス確認を求められ、自動で同意されることはありません。

ゲームごとに独立した Windows 環境を持ち、1 つのゲームを停止しても他の環境のゲームは終了しません。ランタイムをアンインストールしても環境とその中のデータは保持されます。セーブデータ（「存档」）はゲームフォルダ内や環境の内部にあることがあり、自動で特定できない場合はセーブデータページで手動指定してください。環境ディレクトリを直接削除しないでください。Wine はセキュリティサンドボックスではないため、信頼できる入手元のプログラムだけを実行してください。中国語の字形が欠ける場合やゲーム専用フォントがない場合は、対応するフォントのインストールが必要なことがあります。

### どのファイルを選べばいいですか？ZIP を直接追加できますか？

先にゲームを安定した場所に完全に解凍し、ゲームを追加（「添加游戏」）でゲームフォルダ内の任意のファイルを選択します。実行ファイルである必要はなく、`.app` バンドルでもかまいません。アプリはフォルダ構成からエンジンを認識します。認識されたフォルダを確認し、1 つのファイルだけをコピーして残りのデータを失わないようにしてください。

自動認識が正しくない場合は、フォルダ構成が完全かどうかを確認し、追加時にエンジンを確認してください。診断する前にゲームフォルダを移動したり名前を変更したりしないでください。

### ゲームがたくさんあります。一度に追加できますか？

ゲームライブラリ（「游戏库」）の上部バーに「一括操作 → 一括追加」（「批量操作 → 批量入库」）があります。集合フォルダを選び、スキャンを待ってから、各項目のエンジンとタイトルを確認してチェックを入れます。保存前にフォルダと重複を再確認し、選択した項目のいずれかが不正な場合はバッチ全体が書き込まれません。依存関係の不足は明示され、追加した後もランタイムページでインストールが必要です。Wine の候補は実際の起動ファイルの確認が必要です。

スキャンには 3 段階の深さと、2000 フォルダ・200 候補の上限があります。ZIP はスキャンせず、サブフォルダのシンボリックリンクをたどらず、すでに認識したゲームの内部にも入りません。上限に達したという表示が出たときは、より小さなフォルダに分けてスキャンしてください。認識できないゲームは単体追加を使い、エンジンを手動で確認してください。DLsite の作品情報を自動で要求したり選択したりすることはありません。

### ゲームを移動した後、削除して追加し直す必要がありますか？

いいえ。詳細のその他のメニューにあるゲームフォルダを再指定…（「重新定位游戏目录…」）を使います。先にゲームを終了し、移動後の同じゲームフォルダを選択します。認識されるエンジンが一致している必要があり、同じエンジンだけでは同じゲームだと証明できないため、作品の同一性も手動で確認します。元の番号、分類、メタデータ、プレイ記録は保持されます。誤ったフォルダや、すでに他の記録に関連付けられたフォルダは保存されません。

この操作はファイルを移動せず、セーブデータの移動や統合も行いません。元のゲームがセーブデータを別の場所に置いていた場合は、実際のセーブ位置に従って移行とバックアップが必要です。

### 起動診断は何をしますか？

ゲーム詳細のその他（「更多」）メニューにある起動条件を確認（「检查启动条件」）では、ゲームフォルダが存在するか、現在のエンジンが起動に対応しているか、ランタイムのバイナリが見つかり実行権限があるか、今回使用する作業ディレクトリと引数を確認できます。確認のみでゲームは起動しません。mkxp-z でも、診断によって Game.ini を変更したり、パスエイリアスを作成したり、mkxp.json を上書きしたりすることはありません。

診断でフォルダが存在しないと表示された場合はゲームフォルダを再指定（「重新定位游戏目录」）を使ってください。ランタイムが見つからない、または実行権限がないと表示された場合は、ランタイム（「运行时」）ページでインストールまたは修復してください。プロセスがすでに実行中の場合は、二重起動できないことだけを表示し、ゲームを停止することはありません。

### ランタイムは入れたのに、なぜまだ起動に失敗しますか？

ランタイムのインストール完了は依存関係が用意できたというだけで、特定のゲームの互換性を意味しません。次の順に確認してください:

1. ゲームが完全に解凍され、追加したパスがまだ存在するか。
2. エンジンの認識が正しく、対応するランタイムがインストール済みか。
3. 詳細のエンジン管理にあるエンジン引数、ランタイムのバージョンとパスが妥当か。
4. 同じゲームがすでに実行中でないか、初期化エラーやゲーム自身のエラーウィンドウが出ていないか。

報告の際は、アプリのバージョン、OS のバージョン、チップ、ゲームのバージョン、エンジン、再現手順を添えてください。公開されている RJ 番号や作品ページで十分で、ゲーム本体をアップロードする必要はありません。

### オフラインで使えますか？

ローカルのゲームを追加しゲームライブラリを管理するのに、DLsite へのログインは必要ありません。インストール済みのランタイムを毎回ダウンロードし直す必要もありませんが、作品本体やその起動環境にはネットワークが必要な場合があります。

ランタイムのインストール、DLsite の作品情報の取得、ネットワーク上のカバーの読み込みには、それぞれのサイトへのアクセスが必要です。ネットワークに失敗したときは、プロキシと対象サイトへの到達性を確認してください。依存関係をダウンロードできないことを、そのままゲームの非互換と判断しないでください。

## 翻訳とチート

### 起動できるエンジンはすべて翻訳とチートができますか？

いいえ。現在アシスト（「辅助」）が対応しているのは RPG Maker MV/MZ、XP/VX/VX Ace、Ren’Py、Tyrano で、エンジンごとに操作範囲が異なります。ランタイムページには起動・翻訳・チートの能力がそれぞれ表示されます。これらはアプリに同梱された内蔵モジュールで、別途プラグインをインストールする必要はなく、同じエンジンのすべての作品が互換という意味でもありません。

Tyrano は現在 NW.js で開けるディレクトリを対象としており、Electron／ASAR の原本を直接サポートしません。画像内の文字、自前描画の文字、特殊なプラグインは翻訳できる保証がありません。Ren’Py と Tyrano のチートは単純な変数を対象とし、任意のプロセスメモリ改変ではありません。詳しい境界は[翻訳とチート](translation-and-cheats.md)を参照してください。

### 自動翻訳には自分で AI の API を用意する必要がありますか？

必要です。ゲーム詳細の翻訳とチート（「翻译与作弊」）ページで、任意の AI サービスの完全なエンドポイント URL、モデル、キーを入力します。リモートサービスは HTTPS のみ許可され、ローカルサービスは HTTP も使えます。ゲームのテキストは入力したサービスに送信され、費用が発生する場合があります。キーは macOS のキーチェーンに保存され、ゲームフォルダには書き込まれません。

オンラインの自動翻訳を使わずに、原文から訳文への JSON 辞書を読み込んだり、手動で修正したりすることもできます。読み込み済みの訳文はランチャーが常時ネット接続している必要はありませんが、ゲームに追従して訳す場合はランチャーを開いたままにする必要があります。

### アシストを外すとチートの変更は元に戻りますか？

戻りません。数値、アイテム、ストーリーの状態はすでにセーブデータに書き込まれている場合があり、削除は本ツールのアシスト導線とファイルを片付けるだけで、ゲームの進行は復元しません。先にセーブデータをバックアップし、ゲームを終了してからアシストを適用または削除してください。セーブデータを読み込むと古いロックは解除されますが、保存済みの変更は取り消されません。

## 作品情報とセーブデータ

### 作品が見つからない、または同名の結果に一致した場合は？

詳細ページで作品を検索…（「查找作品…」）をクリックすると、作品名、RJ 番号、または DLsite の作品リンクの貼り付けができます。名前検索は成人向けと全年齢の作品をまとめて検索し、範囲を手動で選ぶ必要はありません。RJ 番号は所属区分を自動で特定し、作品リンクはその区分を引き継ぎます。本当に結果がない場合は、翻訳／バージョンの接尾辞やアンダースコアを取り除く処理を試み、試したキーワードを画面に表示します。中国語の訳名と原名が確実に対応しない場合は、日本語の原名、英語名、または作品リンクを使ってください。推測で自動的に一致させることはありません。

候補にはカバー、作品名、サークル、番号が表示されます。プレビュー（「预览」）をクリックして詳細を確認し、この作品に関連付ける（「确认关联此作品」）を押します。アプリは先頭の項目があなたのゲームだと決めつけることはなく、本編、追加コンテンツ、異なるバージョンは確認が必要です。取得に失敗した場合は候補とキーワードが保持され、一部のサイト区分への要求が失敗した場合は他の分類で見つかった候補が保持され、その旨が明示されます。ネットワーク障害、検証ページ、本当に結果がない状態は別々に表示されます。

作品情報は、完全な紹介、発売日、シリーズ、ジャンルタグ、言語、制作／声優、原作の対応システム、プレビュー画像に対応し、欠けている項目は推測しません。ページに表示される言語と対応システムは原作の情報であり、ローカルの翻訳パッチの言語や Mac 上での実際の互換性を保証しません。タグ、サークル、シリーズ、原作の作品名、RJ 番号はゲームライブラリの検索に使えます。

タイトル、サークル、紹介文、その他の作品情報（「更多作品信息」）の項目は手動で編集でき、同じ作品を更新しても手動の修正内容は保持されます。作品を変更するには詳細ページの関連付けを変更…（「更换关联…」）を使い、プレビューで確認した後にのみ置き換えます。古い作品の手動項目が新しい作品に混ざることはなく、ライブラリの名前とセーブデータは変わりません。自動分類は新しい作品の種類に従い、手動で調整した分類は保持されます。更新や関連付けの変更に失敗した場合、元の情報は置き換えられません。

リクエストは自動的に 800ms 以上の間隔でスケジュールされ、待機中／取得中の処理はキャンセルできます。普通に続けてクリックしただけで手動の待機と再試行を求めることはありません。カバーとプレビュー画像はダウンロードに成功するとローカルキャッシュに保存され、以後はローカルから優先して読み込みます。初回に取得していない画像は引き続きネットワークが必要です。キャッシュが壊れた場合は再取得し、失敗時は再試行できます。ゲーム素材から適当な 1 枚をカバーとして選ぶことはありません。保存済みの古い情報は自動でオンライン更新されず、情報を更新（「刷新信息」）をクリックすると追加された項目を取得できます。

### 分類は自動で生成されますか？手動の変更は上書きされますか？

確認して保存された作品データはゲームの種類に応じて自動で分類され、プレビューやジャンルタグが最上位の分類を作ることはありません。欠けている、または認識できない種類は推測しません。既存のデータは次にゲームライブラリを読み込むときに分類され、再取得は不要です。

ゲーム編集 → 分類（「编辑游戏 → 分类」）のチェックと解除はすぐに保存され、情報の更新や作品の変更で上書きされません。古いライブラリの既存の所属も手動の選択として保持されます。種類の変化は自動部分だけを更新し、あなたのカスタム所属を消しません。作品の種類に完全に従わせたい場合は、自動分類に戻す（「恢复自动分类」）を使って確認してください。これはそのゲームの手動分類の調整をすべて消去します。

作品種類の分類は名前を変更でき、由来と所属は変わりません。この分類を削除しても、更新で復活することはありません。同じ名前の既定種類の分類を新しく作る（例: ロールプレイング（「角色扮演」））と再び有効になります。1 つのゲームの自動分類を戻しても、全体の削除は取り消されません。

### ゲームライブラリから削除するときに一部の片付けしか完了していないと表示されたら？

削除する前にゲームライブラリ、作品データ、プレイ記録を確認し、順に片付けます。複数のファイルは 1 つのトランザクションではありません。途中で失敗した場合、メッセージにはすでに保存された片付けの範囲が表示され、再試行できるようにライブラリの記録は保持されます。メッセージにある壊れたファイル、バックアップ、権限の問題を先に解決してから再度削除してください。完了済みの片付けによって番号が新しいゲームに解放されることはありません。この操作はゲームフォルダとセーブデータを削除しません。

### 中国語の情報を優先して取得できますか？DLsite にないゲームは？

開発ソースでは設定 → 作品情報（「设置 → 作品信息」）が追加され、情報の優先言語とフォールバック言語を設定できますが、古い情報を自動で書き換えることはありません。商品ページの言語とゲームの対応言語は別物で、サイトが翻訳していない項目は原文のままのことがあります。異なる RJ の翻訳版が自動で関連付け替えられることはありません。

検索ウィンドウにはその他のゲーム · AI／手動（「其他游戏 · AI／手动」）が追加されました。公開されている公式サイト／ストアページを AI に整理させることができ、独立した Tavily／SearXNG／カスタム検索を使うか、`web_search` に対応した Responses エンドポイントで名前から候補を検索し、ページを選んでプレビューを生成することもできます。通常のチャットモデルは独立した検索と組み合わせられ、エンドポイントがない場合は手動で入力できます。情報は先にプレビューし、項目を選んでから保存します。キーは別途キーチェーンに保存され、RJ を偽造せず、ゲームファイルを自動でアップロードすることもありません。関連機能はまだ新しいインストーラに含まれておらず、設定方法、費用、互換性の制限は[作品情報の取得](game-info.md)を参照してください。

### 作品情報を一括で補完するには？

サイドバーのゲームライブラリ右側メニューにある作品情報の一括補完（「批量补全作品信息」）は、現在の検索と分類フィルタの範囲内のゲームを準備します。既定では未関連付けの作品のみを処理し、既存の情報を補完・更新する選択もできます。開始前にリストを確認できます。

一意な RJ 番号は直接取得して保存します。複数の番号が検出された場合や、名前検索で候補が見つかった場合は確認待ち（「待确认」）で止まり、検索して確認（「查找并确认」）で 1 件ずつプレビューしてから関連付けます。先頭の項目を自動で選ぶことは決してありません。既存の作品を更新する場合は手動の修正が保持され、ライブラリ内のゲーム名とセーブデータは変わりません。分類は作品の種類に従って更新され、手動で追加・削除した所属は保持されます。

処理は 1 件ずつ行われ、失敗しても後続の項目を止めません。失敗した項目を再試行（「重试失败项」）は失敗した項目だけを再処理し、成功した項目を再度更新しません。まだ開始していない項目は補完を続ける（「继续补全」）で処理します。補完ウィンドウを一時停止または閉じると現在のリクエストはキャンセルされ、保存済みの項目は保持されます。今回のアプリ実行中に開き直せば未完了の項目を続けられます。アプリを終了するとタスクリストは保持されず、開き直したときにリストを準備し直せますが、保存済みの作品情報は失われません。リストを準備し直す（「重新准备列表」）は現在のフィルタでリストを作り直し、保存済みの情報は取り消しません。

### セーブデータはどこにありますか？「場所不明」と「空のセーブデータ」の違いは？

ゲーム詳細のセーブデータ（「存档」）ページで確認します。場所はゲームとエンジンによって異なり、必ずしも Tsumigeya のアプリデータディレクトリ内とは限りません。

- **場所不明**（「位置未知」）: アプリがまだそのゲームのセーブフォルダを特定できていません。TyranoScript と吉里吉里はパスを自動で推測しません。
- **フォルダが空、またはまだセーブデータがない**: アプリは場所を特定しましたが、表示できるセーブデータが見つかりませんでした。

実際の場所がわかっている場合は、セーブフォルダを選択…（「选择存档目录…」）をクリックして手動で指定できます。この操作はフォルダを記録するだけで、ファイルの移動や統合は行いません。フォルダは空でもかまいません。移動または削除されたフォルダは引き続き不明として表示され、空のセーブデータを装うことはありません。Finder で表示（「在访达中显示」）をクリックすると現在のフォルダを開け、コピーボタンは完全なパスをコピーします。自動検出に戻す（「恢复自动探测」）をクリックすると手動指定を解除できます。ゲームの実行中はフォルダを変更できません。

### バックアップや移行は？クラウド同期には対応していますか？

先にゲームを終了し、セーブデータページから ZIP を書き出します。移行先の環境で対応するゲームを追加し、セーブ位置を確認してからインポート機能で復元します。

書き出しには一般的なセーブスロットだけでなく、セーブフォルダ全体が含まれます。インポートは先に内容を検証し、その後に既存のファイルをバックアップします。インポートのバックアップは通常 `.tsumigeya-bak` で終わり、同名のバックアップは上書きされません。そのためにインポートが失敗した場合は、まずバックアップを確認して大切に保管し、直接削除しないでください。

現在**クラウド同期はありません**。書き出した ZIP はご自身で保管してください。ゲームライブラリを移行する場合は、アプリデータディレクトリとゲーム本体も別途コピーする必要があります。アプリデータ、ゲーム、セーブデータは 3 つの別のものです。

### 画面やログをそのまま Issue に貼れますか？

貼れますが、先に氏名、個人のディレクトリ、アカウント情報、トークン、私的な内容を隠してください。商業ゲームの本体、有料素材、未公開のパッチ、私的なセーブデータを添付しないでください。

スクリーンショットや共有の前に画面を自分で確認し、必要なら私的な内容を切り取るか隠してください。

### ローカルモデルと Tavily を組み合わせられますか？LAN の HTTP がブロックされるのはなぜ？

組み合わせられます。検索サービスとモデルは別々に設定し、キーも別々に保存します。検索は、モデルがネイティブにネット接続できることやツール呼び出しに対応していることを要求しません。候補を選ぶと、実際のページはローカルモデルが整理します。LAN の HTTP は作品情報設定で現在の完全なアドレスに対して個別に許可し、アドレスを変更したら取り消す必要があります。許可してもファイアウォールは開放されず、イントラネットのページをスクレイピングすることもできません。モデルが別のコンピュータのループバックアドレスだけを待ち受けている場合、IP を変えるだけでは接続できず、待ち受けを安全に設定するか暗号化トンネルを使う必要があります。詳しくは[作品情報の取得](game-info.md)を参照してください。
