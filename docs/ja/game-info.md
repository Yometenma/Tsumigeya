# 作品情報の取得

[English](../en/game-info.md) · [简体中文](../作品信息获取.md) · **日本語**

> Tsumigeya の画面は現在、簡体字中国語のみです。画面内の項目名は「」で実際の表記のまま引用し、初出時に日本語名を添えています。

このページは v3.0.0 の作品情報機能について説明します。情報の補完はゲームの起動互換性を変えず、ゲーム本体をダウンロードすることもありません。

## 情報の言語を選ぶ

**設定 → 作品情報**（「设置 → 作品信息」）で「作品信息优先语言」（優先言語）と「缺失时回退语言」（欠落時のフォールバック言語）を設定します。簡体字中国語、繁体字中国語、日本語、英語、韓国語に対応し、既定では簡体字中国語を優先して日本語にフォールバックします。フォールバックはオフにすることもできます。

- 単体の検索、候補のプレビュー、更新、DLsite の一括補完はすべて同じ設定を使います。設定を切り替えても、保存済みの情報が自動でネットワーク経由に書き換わることはありません。既存の作品は手動で更新してください。
- リクエストは DLsite 商品ページの言語を明示的に指定し、キャッシュは RJ とリクエスト言語ごとに分けて保存するため、中国語のリクエストが以前の英語キャッシュに当たることはありません。古いキャッシュは残しますが、新しい言語のキャッシュとしては使いません。
- 対象の商品ページが利用できない、または別のページ言語が明示的に返された場合は、同じ RJ のフォールバック言語を試します。検索結果が無い場合もフォールバック言語を試せます。オフライン、認証ページ、サービス障害は“その言語が無い”ことに偽装されません。
- **ページの言語はゲームの言語ではありません**。DLsite にはサイトのナビゲーションだけを翻訳し、タイトルや本文は原文のままの商品もあります。そのような項目はサイトの実際の内容をそのまま保持し、メニューの言語だけで説明全体が翻訳済みだとは主張しません。ページに言語の記載が無い場合は“未記載”と表示します。
- 別の RJ の翻訳版、追加コンテンツ、リメイクへ自動で切り替わることはありません。番号が異なる場合は、関連付けをあなたが確認して承認する必要があります。

AI による整理も作品情報の優先言語を使いますが、出典内の文章を翻訳・整理するだけで、それをもとに“ゲームの対応言語”を埋めることはありません。画面の言語とゲーム翻訳のインターフェースは独立したままです。

## DLsite に無いゲーム

まずローカルゲームを通常どおり追加し、**ゲーム詳細 → 作品を検索／情報を補完または変更 → その他のゲーム · AI／手動**（「游戏详情 → 查找作品／补全或更换资料 → 其他游戏 · AI／手动」）で操作を選びます。

### 方法 1：公開ページを指定する

1. 設定で作品情報のインターフェースとモデルを構成し、キーをキー欄に入力して単独で保存します。
2. 公式サイトやストアの **HTTPS 商品ページのリンク** を貼り付け、送信内容と費用の注意を確認してから「读取并整理页面」（ページを読み取って整理）をクリックします。
3. アプリは必要な本文を読み取り、モデルに整理を任せます。モデルが提出できるのは元ページからの引用を伴う項目だけで、確認できない項目は無視されます。日付は出典の原文も保持する必要があり、推測で埋めることはできません。
4. プレビューでタイトル、開発元／販売元、紹介文、日付、シリーズ、タグ、言語、制作／声優、原作システムなどの情報を確認し、必要な項目を選びます。直接編集することもできます。
5. 「确认保存所选信息」（選択した情報を保存）をクリックして初めて書き込まれます。キャンセルや閉じる操作では元の情報は変更されません。

カバー画像はページ自身の共有画像情報から取得します。モデルが返した画像アドレスは採用せず、公式カバーを装う画像を生成することもありません。カバーの保存を省略するか、公開 HTTPS の画像アドレスを手動で入力できます。ローカルの画像やゲーム素材は読み取りません。第三者の画像はリダイレクトを追わないため、直リンク防止やリダイレクトのある画像は表示できない場合があります。

現時点では公開され直接アクセスできる UTF-8 の HTML のみを読み取り、Web スクリプトは実行せず、ブラウザのログイン Cookie も持ち込みません。ログインページ、年齢確認、bot 対策の認証、動的読み込み、本文が長すぎる場合、ページがアクセスを拒否する場合は失敗することがあります。別の公開ページを使うか、手動で入力してください。

### 方法 2：ゲーム名でネット検索する

**設定 → 作品情報 → 搜索来源**（検索ソース）で検索方法を選び、ゲーム名を入力します。開発元や年などの手がかりを追加できます。

- **モデル本来のネット接続**：Responses インターフェースと `web_search` に対応したモデルサービスが必要で、候補はインターフェースが返した出典引用のみを採用します。
- **独立検索 · Tavily**：検索キーを単独で保存します。検索アドレスを空にすると公式の検索インターフェースを使います。アプリは作品情報の優先言語で基本検索を 1 回だけ行い（厳密な言語フィルタではなく優先指定）、自動検索パラメータは有効にせず、AI の回答や完全なページ本文も要求しません。候補は最大十二件で、画面では三／五／十件を選べます。
- **独立検索 · SearXNG**：インスタンスの完全な検索アドレスを入力します。インスタンスは JSON 出力を有効にする必要があります。キーが必要かどうかはあなたのサービス次第です。公開インスタンスはレート制限や JSON の無効化がある場合があります。
- **独立検索 · カスタムインターフェース**：GET のクエリパラメータまたは POST JSON に対応し、キーワードのパラメータ名と、ドット区切りの結果フィールドパスを設定できます。既定では `results` 配列と各項目の `title`、`url`、`content` を読み取ります。結果配列のパスを空にするとルート配列を意味します。追加パラメータには機密でない JSON のみを入力し、別途確認して保存する必要があります。認証は独立した Bearer キーのみに対応します。他の認証方式が必要なサービスは自前の変換サービス経由で接続してください。キーをクエリパラメータに入れることはできません。
- **ネット検索をオフ**：ページを指定した整理や手動入力は引き続き利用できます。

独立検索はアプリが実行するため、**通常のチャットモデルはツール呼び出しや自前のネット接続に対応している必要はありません**。モデルがツール呼び出しに対応していても、現在は“検索 → 人が出典を選ぶ → モデルが整理する”という固定の流れで実行し、モデルに自律的な検索ループをさせることはありません。各操作で呼ぶのは選択した検索サービスだけで、失敗しても自動で再試行したり有料サービスに切り替えたりしません。

候補にはタイトル、出典リンク、利用可能な要約を表示し、公開 HTTPS のリンクのみを受け付けて重複を除きます。モデルの本文からアドレスを勝手に抜き出すことはせず、先頭の候補があなたのゲームだと自動で決めつけることもありません。検索の要約は識別の手がかりにすぎず、そのまま正式な情報として保存されることはありません。出典を選んでからページを読み取り、モデルが確認待ちの情報を生成します。独立検索だけならモデルの設定は不要ですが、ページの整理にはモデルが必要です。

### 方法 3：完全に手動で入力する

「手动填写…」（手動で入力…）をクリックすると情報を入力できます。インターフェースやキーは不要で、ネットにも接続しません。タイトルは必須で、その他の不明な項目は空のままで構いません。保存後も「编辑游戏」（ゲームを編集）から変更できます。

## インターフェース、認証情報、費用

作品情報のインターフェースとゲーム翻訳のインターフェースは別々に設定し、アドレスには完全なリクエストパスを入力します。例：

```text
チャット互換インターフェース：https://api.example.com/v1/chat/completions
Responses インターフェース：https://api.example.com/v1/responses
```

上記のアドレスは形式を示すだけで、そのまま使えるサービスではありません。モデル名と検索の対応はあなたのサービス提供元によります。既定の有料モデルは組み込まれていません。既定では HTTPS のみ、または明示的に設定した `localhost`／`127.0.0.1` のローカル HTTP サービスのみを受け付けます。LAN の HTTP には後述の個別承認が必要です。インターフェースのアドレスにアカウント、パスワード、クエリパラメータを含めることはできません。キーは専用のキー欄に入力してください。

- キーはインターフェースのアドレスごとに macOS のキーチェーンに保存し、ゲームライブラリ、通常の設定、ログには書き込みません。アドレスを切り替えても別のアドレスのキーは引き継ぎません。
- 呼び出しは明確に確認した後だけ行います。ページを指定した場合は必要な本文と出典アドレスを、名前で検索した場合は入力した名前と補足の手がかりを送信します。検索もモデル呼び出しも課金される場合があります。
- ゲーム本体、セーブデータ、プライベートなフォルダ、ゲームライブラリ全体を自動でアップロードすることはありません。公開ページでもそのページを提供するサイトへリクエストが発生します。ローカル、イントラネット、ファイルのアドレスは読み取りません。
- DLsite の一括補完は有料 AI を自動で呼びません。既存の外部情報はスキップされ、作品ごとにプレビューして確認する必要があります。
- AI は実際の引用を伴っていても誤解することがあります。引用は確認の手がかりであり、事実の保証ではありません。重要な情報は人が確認する必要があります。

## LAN とローカルモデル

モデルと検索のインターフェースには、それぞれ独立した **「授权当前局域网接口」**（現在の LAN インターフェースを承認）スイッチがあります。完全な HTTP アドレスを入力したうえでオンにし、リスクの注意を確認して初めてそのアドレスへの接続が許可されます。アドレス、ポート、パスを変更すると自動的に取り消され、検索方法を切り替えた場合も検索の承認が取り消されます。モデルの承認は検索の承認ではなく、取り消すと現在の情報タスクも中止されます。プライベート IPv4、IPv6 ULA、ローカルサービス名に対応します。このスイッチで公衆ネットワークの平文 HTTP を承認することはできません。

HTTP は暗号化されないため、本文やキーがネットワーク上の他の機器に読まれる可能性があります。信頼できるネットワークでのみ使い、HTTPS や暗号化トンネルを推奨します。アプリはポートを自動で開放せず、ファイアウォールやサービスの待ち受け設定も変更しません。**Web ページの本文と画像は引き続き公開 HTTPS のみ**で、インターフェースを承認したからといってイントラネットのページを読み取ることはありません。

モデルが別のコンピュータにある場合、Mac の `127.0.0.1` はそのコンピュータを指しません。サービスが自分のマシンだけで待ち受けている場合、単に LAN の IP に変えても接続できません。サービスを自分で安全に LAN 待ち受けに設定するか、暗号化トンネルを使ってください。アドレスには `/v1/chat/completions` などの実際のパスを含め、モデル名はサービスのモデル一覧に従って入力し、表示名から推測しないでください。

**「本地模型与兼容选项」**（ローカルモデルと互換オプション）では次を調整できます。

- モデルの待ち時間上限：九十秒、三分、五分、十分。既定は三分。
- 1 回の本文長：八千〜四万五千字。既定は一万六千字。超えた部分は切り捨てられ、カバーされない項目は欠ける場合があります。自動で分割して呼び出しを増やすことはありません。
- JSON オブジェクト出力：サービスが対応している場合のみ有効、既定はオフ。非対応なら失敗を通知し、黙ってフォールバックして再試行することはありません。
- 互換モデルの思考モードをオフにする：チャットプロトコルのみ `chat_template_kwargs.enable_thinking=false` を送信します。既定はオフで、サービスの対応が必要です。

モデルが別途返す思考フィールドは情報として読み取りません。本文冒頭の完全な `<think>…</think>` は除去できます。思考のみ、思考が閉じていない、解析できない回答は保存されません。種別には明確な種別語を含む原文引用が必要で、ゲーム内容の説明だけから分類を推測することはできません。その他の項目も誤解される可能性があるため、プレビューで確認してください。

## 保存と更新

外部情報は出典を別に記録し、RJ を偽造せず、DLsite の作品を装うこともありません。旧版の DLsite メタデータとの互換性を保ちます。情報、出典の引用、手動編集のマークはゲームライブラリの隣のサイドカーファイルに保存し、分類と未知の拡張フィールドは保持します。

同じ出典の更新では手動で編集した項目を保持します。チェックしていない項目はその作品の既存値を保持し、欠落していても空にはしません。出典を変更するとプレビューで注意が表示され、古い作品の情報は混ざりません。手で変更した項目は元の AI 引用による裏付けを持たなくなりますが、出典の記録は確認用に残ります。

元のゲーム名、ファイル、セーブデータは変わりません。自動分類は確認済みの作品種別に応じて更新され、手動での分類調整は保持されます。外部の出典 URL が情報の識別子になるため、別のアドレスに変えると出典の変更として扱われます。表示される注意を確認してください。
