# 常见问题

[返回项目首页](../README.md) · [下载最新版](https://github.com/Yometenma/Tsumigeya/releases/latest) · [报告问题](https://github.com/Yometenma/Tsumigeya/issues/new/choose)

## 安装与更新

### 支持哪些 Mac？

当前安装包需要 **macOS 26 或更新版本和 Apple Silicon**。不提供 Intel 安装包，也不提供 Windows 或 Linux 的原生版。

<a id="first-launch"></a>

### 首次打开提示“无法验证开发者”或“应用已损坏”怎么办？

先确认安装包来自本仓库的 Releases，而不是不明来源的转载。当前应用仅做 ad-hoc 签名，没有 Developer ID 分发签名，也未经过 Apple 公证，因此可能被 Gatekeeper 拦截。

如果信任来源，可对已经放入「应用程序」的应用执行：

```bash
xattr -dr com.apple.quarantine /Applications/Tsumigeya.app
```

这会移除该应用的下载隔离标记，不是公证或安全证明。**不要关闭系统整体安全保护。** 如果提示仍然存在，不要把所有问题都归因于隔离标记；重新下载安装包，并检查下载是否完整。

发布附件中的 `SHA256SUMS.txt` 记录安装包校验值。在下载目录中可查看安装包的 SHA-256，并与该版本的校验文件逐项比较：

```bash
shasum -a 256 Tsumigeya-*.dmg
```

如果应用未安装在 `/Applications`，命令中的路径也需要相应调整。

### 如何更新？会丢游戏库吗？

退出 Tsumigeya，下载新版 DMG，再替换「应用程序」中的旧应用。应用数据与 `.app` 分开存储，当前版本使用以下目录：

```text
~/Library/Application Support/Tsumigeya/
```

更新前仍建议备份应用数据和真实游戏存档。不同历史版本的迁移说明以对应 Release 为准；不要删除应用数据目录来“清理旧版本”。

## 游戏与运行时

### 它能运行任意 Windows 游戏吗？

不能保证任意 Windows 游戏。Tsumigeya 通过 Wine 启动确认过的 Windows `.exe`，但驱动、反作弊、DRM、特殊图形接口和额外依赖都可能导致程序不兼容。Unity、RPG Developer Bakin、WOLF RPG Editor 的旧记录会按 Wine 读取，不再单独列为“仅识别”。

识别引擎并不等于保证兼容。插件、脚本扩展、加密方式和依赖都可能影响结果。具体范围见 [游戏兼容性](../README.md#游戏兼容性)。

### Wine 怎么使用？

在「引擎管理」页安装「Wine（Windows 兼容）」，然后添加完整解压的游戏。Windows 游戏也可选择目录内的说明等普通文件来识别；只有一个 EXE 时会自动填写，有多个时需确认真正的启动文件，而不是安装器或卸载器。已有专用 macOS 运行时的游戏仍优先使用原有运行时。

在「编辑游戏」中可调整 Windows 启动文件、逐行启动参数和中／日／英语言环境；「引擎管理 → Windows 环境设置…」可调整 Windows 版本、音频和 DLL 等设置。首次启动需要初始化环境，耗时会比后续启动长。Apple 芯片 Mac 缺少 Rosetta 2 时，会先请求确认 Apple 许可，不会自动同意。

每个游戏拥有独立的 Windows 环境，停止一个游戏不会结束其他环境中的游戏；卸载运行时会保留环境及其中的数据。存档可能在游戏目录或环境内部，无法自动定位时请在「存档」页手动指定，不要直接删除环境目录。Wine 不是安全沙盒，只运行可信来源的程序。中文缺字或游戏专用字体缺失仍可能需要安装相应字体。

### 应该选择哪个文件？可以直接添加 ZIP 吗？

先把游戏完整解压到一个稳定的位置，再在「添加游戏」中选择游戏目录内的任意文件，不必一定是可执行文件，`.app` 包也可以。应用会按目录结构识别引擎；请核对识别出的目录，不要单独复制一个文件而丢掉其余数据。

如果自动识别不正确，确认目录结构完整，并在添加时检查引擎。诊断前先不要移动或重命名游戏目录。

### 有很多游戏，可以一次添加吗？

游戏库顶栏提供「批量操作 → 批量入库」：选集合目录，等待扫描，再逐项核对引擎、标题并勾选。保存前会重新检查目录和重复项；任一选中项不合法时整个批次都不写入。依赖缺失会明确提示，入库后仍需到运行时页安装；Wine 候选需要确认实际启动文件。

扫描有三层深度、2000 个目录和 200 个候选的上限，不扫描 ZIP、不跟随子目录符号链接，也不会深入已经识别出的游戏。提示达到上限时可分小目录扫描。不能识别的游戏请使用单个添加，手工确认引擎。不会自动请求或选择 DLsite 作品信息。

### 游戏搬家后需要删除重加吗？

不需要。在详情的更多菜单使用「重新定位游戏目录…」。先退出游戏，选择移动后的同一游戏目录；识别引擎必须匹配，还需手工确认作品身份，因为同一引擎不能证明是同一部游戏。原编号、分类、元数据和游玩记录会保留。错误目录或已关联其他记录的目录不会保存。

该操作不移动文件，也不搬移或合并存档。原游戏若把存档放在独立位置，仍需按实际存档位置迁移和备份。

### 启动诊断会做什么？

在游戏详情的「更多」菜单中选择「检查启动条件」，可以查看游戏目录是否存在、当前引擎是否支持启动、运行时二进制是否找到且有执行权限，以及本次会使用的工作目录和参数。它只检查，不会启动游戏；对 mkxp-z 也不会因为诊断而修改 Game.ini、创建路径别名或覆盖 mkxp.json。

如果诊断提示目录不存在，请使用「重新定位游戏目录」；如果提示运行时缺失或没有执行权限，请到「运行时」页安装或修复。进程已经运行时，诊断只提示不能重复启动，不会替你停止游戏。

### 运行时装好了，为什么还是启动失败？

运行时安装完成只代表依赖已经准备好，不代表具体游戏兼容。可按顺序检查：

1. 游戏是否完整解压，添加的路径是否仍存在。
2. 引擎识别是否正确，对应运行时是否安装完成。
3. 详情「引擎管理」中的引擎参数、运行时版本和路径是否合理。
4. 同一游戏是否已在运行，是否出现初始化错误或游戏自己的报错窗口。

反馈时请提供应用版本、系统版本、芯片、游戏版本、引擎和复现步骤。可以提供公开的 RJ 编号或作品页面，不需要上传游戏本体。

### 可以离线使用吗？

添加本地游戏和管理游戏库不要求先登录 DLsite。已安装的运行时也无需每次重新下载，但作品本身或其启动环境可能仍有网络要求。

安装运行时、抓取 DLsite 作品信息和加载网络封面需要访问相应站点。网络失败时，请检查代理和目标站点的可达性；不要把无法下载依赖直接判断为游戏不兼容。

## 翻译与作弊

### 所有能启动的引擎都能翻译和作弊吗？

不是。当前辅助接入 RPG Maker MV/MZ、XP/VX/VX Ace、Ren’Py 和 Tyrano，各引擎的操作范围不同。「运行时」页会分别列出启动、翻译与作弊能力。它们是随应用提供的内置模块，不需要另装插件，也不代表同引擎的全部作品都兼容。

Tyrano 目前面向可由 NW.js 打开的目录，不能直接支持 Electron／ASAR 原包。图片文字、自绘文字和特殊插件不保证能翻译；Ren’Py 与 Tyrano 的作弊针对简单变量，不是任意进程内存修改。完整边界见 [翻译与作弊说明](翻译与作弊.md)。

### 自动翻译需要自己接 AI 接口吗？

需要。在游戏详情的「翻译与作弊」页填写自选 AI 服务的完整接口地址、模型及密钥；远程服务只允许 HTTPS，本机服务可使用 HTTP。游戏文本会发送到所填服务，可能产生费用；密钥保存在 macOS 钥匙串，不写入游戏目录。

也可以导入原文到译文的 JSON 字典或手动修订，不必使用在线自动翻译。已加载的译文不要求启动器持续联网；跟随游戏补译则需要启动器保持开启。

### 移除辅助能撤销作弊修改吗？

不能。数值、物品和剧情状态可能已经写入存档；移除只清理本工具的辅助入口与文件，不会还原游戏进度。请先备份存档，退出游戏后再应用或移除辅助。读档会解除旧锁定，不会撤销已保存的修改。

## 作品信息与存档

### 搜不到作品，或匹配到同名结果怎么办？

在详情页点击「查找作品…」，可以输入作品名、RJ 编号或粘贴 DLsite 作品链接。名称搜索统一查找成人向与全年龄作品，不需要手动选择范围；RJ 编号自动定位分区，作品链接沿用其分区。确实无结果时会尝试清理汉化／版本后缀与下划线；界面会显示尝试过的关键词。中文译名与原名无法可靠对应时，请换用日文原名、英文名或作品链接，不会凭猜测自动匹配。

候选显示封面、作品名、社团和编号，点击「预览」核对详情后再「确认关联此作品」。应用不会自动认定第一条就是你的游戏，正片、追加内容和不同版本仍需核对。获取失败保留候选和关键词；部分站点分区请求失败时会保留其他分类已找到的候选，并明确提示。网络故障、验证页面与真正无结果分别显示。

作品信息支持完整介绍、发售日期、系列、题材标签、语言、制作／配音、原版支持系统及预览截图，缺失项不臆测。页面标注的语言和支持系统是原版信息，不保证本地汉化包语言或在 Mac 上的实际兼容性。标签、社团、系列、原始作品名及 RJ 编号可用于游戏库搜索。

标题、社团、简介和「更多作品信息」中的字段可手动编辑，刷新同一作品时保留手改内容。更换作品请用详情页的「更换关联…」，预览确认后才替换；旧作品的手改字段不会混入新作品，游戏库名称和存档不变；自动分类跟随新作品类型，手动分类调整仍保留。刷新或换绑失败不替换原有信息。

请求自动按至少 800ms 间隔调度，可取消等待／获取；不会要求用户因普通连续点击而手动等待重试。封面与预览图下载成功后保存在本机缓存，之后优先本地读取；首次未下载的图片仍需联网。缓存损坏会重新获取，失败可重试，不会从游戏素材中随便挑一张当封面。已保存的旧信息不会自动联网升级，点击「刷新信息」可获取新增字段。

### 分类会自动生成吗？手动修改会被覆盖吗？

已确认保存的作品资料会按游戏类型自动归类，预览和题材标签不会创建主分类。缺失或无法识别的类型不猜测。已有资料下次加载游戏库时即可归类，不必重新抓取。

「编辑游戏 → 分类」中的勾选和移除立刻保存，资料刷新或更换作品不会覆盖；旧库已有归属也作为手动选择保留。类型变化只更新自动部分，不清理你的自定义归属。希望重新完全跟随作品类型时，使用「恢复自动分类」并确认；这会清除该游戏的所有人工分类调整。

作品类型分类可重命名，来源和归属不变。删除此类分类后，刷新不会让它复活；新建同名的默认类型分类（如「角色扮演」）可重新启用。恢复单个游戏的自动分类不会撤销全局删除。

### 从游戏库移除时提示只完成部分清理，怎么办？

移除前先检查游戏库、作品资料和游玩记录，再依次清理。多个文件不是一次事务：若中途失败，提示会列出已经保存的清理范围，游戏库记录保留以便重试。先处理提示中的损坏文件、备份或权限问题，再次移除即可；已经完成的清理不会把编号释放给新游戏。此操作不会删除游戏目录和存档。

### 能优先获取中文资料吗？不在 DLsite 上的游戏怎么办？

开发源码新增「设置 → 作品信息」，可设置资料优先语言与回退语言，不会自动重写旧资料。商品页语言与游戏支持语言不同，网站未翻译的字段可能仍是原文；不同 RJ 的翻译版不会自动换绑。

查找窗口新增「其他游戏 · AI／手动」：可以提供公开官网／商店页给 AI 整理，也可通过独立 Tavily／SearXNG／自定义搜索，或支持 `web_search` 的 Responses 接口按名称查候选，再选择页面生成预览。普通聊天模型可搭配独立搜索；无需接口时可直接手动填写。资料先预览、选字段后保存，密钥独立存入钥匙串，不伪造 RJ、不自动上传游戏文件。相关功能尚未随新版安装包发布，配置方式、费用和兼容限制见[作品信息获取](作品信息获取.md)。

### 如何批量补全作品信息？

侧边栏「游戏库」右侧菜单中的「批量补全作品信息」会准备当前搜索和分类筛选范围内的游戏。默认仅处理未关联作品，也可选择补全并刷新已有信息。开始前可核对列表。

唯一 RJ 编号直接获取并保存；检测到多个编号或按名称搜到候选时，停在「待确认」，通过「查找并确认」逐项预览后关联，绝不自动选首条。已有作品刷新保留手动修改，不改库内游戏名称和存档；分类按作品类型更新，保留手动增加和移除的归属。

任务逐项处理，失败不阻断后续项目；「重试失败项」只重新处理失败项，不重复刷新成功项；尚未开始的项目通过「继续补全」处理。暂停或关闭补全窗口会取消当前请求，已保存项保留；在本次应用运行期间重新打开可继续未完成项。退出应用后任务清单不保留，再次打开时可重新准备列表，已保存的作品信息不会丢失。「重新准备列表」按当前筛选重新生成清单，不撤销已保存信息。

### 存档在哪里？“位置未知”和“空存档”有什么区别？

在游戏详情的「存档」页查看。位置取决于游戏和引擎，不一定在 Tsumigeya 的应用数据目录内。

- **位置未知**：应用还不能确定该游戏的存档目录。TyranoScript 和吉里吉里不会自动猜测路径。
- **目录为空或尚无存档**：应用已确定位置，但没有找到可展示的存档。

如果知道实际位置，可点击「选择存档目录…」手动指定。这个操作只记录目录，不会移动或合并文件；目录可以是空的。目录被移动或删除后仍会显示为未知，不会伪装成空存档；点击「在访达中显示」可以打开当前目录，复制按钮会复制完整路径；点击「恢复自动探测」可清除手动指定。游戏运行中不能更改目录。

### 如何备份或迁移？支持云同步吗？

先退出游戏，再从「存档」页导出 ZIP。在目标环境中添加对应游戏、确认存档位置后，使用导入功能恢复。

导出包含整个存档目录，而不只包含常见存档槽；导入会先校验内容，再备份已有文件。导入备份通常以 `.tsumigeya-bak` 结尾，已有同名备份不会被覆盖；如果因此导入失败，应先核对并妥善保存备份，不要直接删除。

当前**没有云同步**，导出的 ZIP 由你自行保管。迁移游戏库时还应另行复制应用数据目录和游戏本体；应用数据、游戏和存档是三件不同的东西。

### 能把界面或日志直接贴进 Issue 吗？

可以，但请先隐藏姓名、个人目录、账号信息、令牌和私人内容。不要附商业游戏本体、付费素材、未公开补丁或私人存档。

截图或分享前请自行检查画面，必要时裁切或遮挡私人内容。

### 本地模型能否搭配 Tavily？局域网 HTTP 为什么被拦截？

可以，搜索服务与模型分开配置、分开保存密钥。搜索不要求模型原生联网或支持工具调用；选中候选后由本地模型整理实际页面。局域网 HTTP 需在作品信息设置中对当前完整地址单独授权，更换地址后撤销；授权不会开放防火墙，也不会允许刮削内网页面。模型只监听另一台电脑的本机地址时，改 IP 不足以连通，需安全配置监听或使用加密隧道。详见 [作品信息获取](作品信息获取.md)。
