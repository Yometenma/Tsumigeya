## ⚠️ 本次踩到的四个真问题（都有测试守着）

### ① CRLF 的 `split(separator: "\n")` 只切出 1 行 —— **最隐蔽的一个**

```swift
// 错：
text.split(separator: "\n")        // CRLF 文件 → 整份文件变成 1 行！
// 对：
text.components(separatedBy: .newlines)
```

**为什么**：Swift 的 `String` 按 **Character（字素簇）** 比较，而 `\r\n` 是**一个** Character，
`"\n"` 匹配不到它。

**后果（极隐蔽，完全不报错）**：`[Game]` 那行变成 `"[Game]\r\nRTP=...\r\nLibrary=..."` 一整串，
section 变成 `"game]\r\nRTP=..."`（永远不等于 `"game"`），于是 RTP / Library 一个都读不到 →
`rgssVersion` 推不出来 → mkxp.json 只写 gameFolder → **游戏照样能启动**（mkxp-z 自己猜版本）
→ 问题被完全掩盖。

**本机的真实 `Game.ini` 正是 CRLF**（`5b47 616d 655d 0d0a` = `[Game]\r\n`）。

判据：`P2LaunchTests.swift` 的 `crlfSplitsProperly`（含 LF 对照不坏）。

### ② 漏了 `gameArgs` 缺省值合并 → mkxp-z 崩在 `kernel32`

**症状**（用户当场指出「佣兵的冒险明明启动失败了」）：
```
Failed loading .../kernel32: dlopen(...): no such file
from 002:WF-RGSS Scripts rev-29:776:in initialize'
```

**根因**：`preloadScript` 这个参数**没传**，它的 manifest 默认值是
`<dataDir>/modules/mkxpz/deps/kawariki/kawariki/preload.rb` ——
那个 **kawariki 预载脚本**就是给 Ruby 补 Windows API 兼容层的（`kernel32` 正是它提供的）。

不传它 → 脚本加载 `kernel32` 失败。**Electron 版能跑，是因为它有这一步**（本鱼漏了）。

判据：`ManifestTests` 的 reconcile 四条语义 + `Launcher.plan` 必须显示 preloadScript 存在。

### ③ 「进程活着」不等于「游戏跑起来了」

本鱼最初用「spawn 成功 + 2.5 秒后进程还在」当判据 —— **用户立刻反驳了**。

**真相**：mkxp-z 遇到 Ruby 异常**不退出**，它弹错误框等人点确定。
于是进程活着 = 看起来成功，实际卡在错误框上。

**正确判据**（按可靠性）：
1. **窗口存在**（最硬）
2. **CPU 时间在增长**（次硬：卡在弹窗上的进程 CPU 不动）
3. 日志里有正常启动特征（`Path cache completed`）
4. 进程存在性（最弱）

判据：`LaunchProbe.swift`。实测修正前后：修前「判定不了」，修后 CPU 40–170ms/1.2s。

### ④ NW.js 单实例机制会「吃掉」启动请求

用户正在玩 Karryn's Prison 时，本鱼测它 → NW.js 发现已有实例 →
**把请求转给那个实例、自己退出** → 本鱼误判成「启动失败」。

**处置**：启动前先查这个游戏是不是在跑（按**游戏目录路径**匹配 `ps`，不是按引擎名盲杀
——按引擎名会把用户其他游戏一起杀掉）。在跑就跳过。

判据：`runningProcesses(forGame:engine:dataDir:)`。

## 已知限制（诚实记录）

1. **NW.js 在 SSH 会话里判不准「开了几个窗口」**（窗口列表拿不到）→ 靠 CPU 判据兜底。
   真实桌面会话下应该都能看到窗口，但本鱼没法在 SSH 里验这一点。
2. **Karryn's Prison（id=2）没有被本鱼测过启动** —— 用户当时正在玩，跳过了。
3. **SSH 会话下 Chromium/NW.js 会报 Keychain/daemon 警告**
   （`errSecInteractionNotAllowed` / `SetApplicationIsDaemon`），
   这些**不影响游戏**，但会污染日志，判据里要显式排除。
4. **4 个引擎的路径未实现**（kirikiri / nscripter / siglus / godot）——
   用户机器上没装它们，**不凭猜写路径**（猜出来的"看起来对"但启动才失败，
   而且失败原因会指向"引擎装坏了"）。P3 装上真实引擎后按 `deps/` 下实际布局补。
5. **UI 完全没写**。
