# M4.0 实施方案：去掉上游 launcher（自实现启动）

> **状态：待实施。** 用户 2026-11-04 决定：**「只砍 launcher，保留 module.js」**，
> 且 **M3.5 已完成**（v0.3.2），现在可以开工。
>
> 前置阅读：[`docs/调研-去掉上游launcher的可行性.md`](./调研-去掉上游launcher的可行性.md)（**已实测的结论，别重复验证**）
>
> 基线：M1–M3.5 全绿，**507 tests / 20 files**，v0.3.2 已发布。

---

## 1. 为什么做

### 1.1 三个动机

| # | 动机 | 严重度 |
|---|---|---|
| **A** | **不再修改用户的游戏文件**（上游 nwjs 会改写 `js/main.js`、塞 `js/plugins/Cheat_Menu.js`、改 `package.json`） | ⭐⭐⭐⭐ |
| **B** | **摆脱「必须共享 `xenolauncher` 数据目录」**（D3 的由来） | ⭐⭐⭐ |
| **C** | **清掉一批补丁式代码**（`reconcileVersionArgs`、nwjs 二进制预检查） | ⭐⭐⭐ |

### 1.2 顺带的额外收益

- 进程追踪变**简单**（自己 `spawn` 直接有 PID，不用劫持 `exec`）
- 启动失败**有真实错误**（`spawn` 的 ENOENT 会抛，上游 `exec` 只 `console.error`）

## 2. 已实测的关键事实（**别重复验证**）

### 2.1 上游 launcher 里 99% 是附加功能

| 引擎 | 总行数 | 真正启动所在行 |
|---|---|---|
| nwjs | 542 | 534 |
| mkxpz | 242 | 234 |
| easyrpg | 123 | ≈120 |
| renpy | 69 | 60 |

**nwjs 那 533 行**：`copyCheatFiles` / `modifyMVMainJs`（**改写游戏 `js/main.js`**）/
`applyProtection` / `addChromiumArg` / `patchRpgmGetPixel` —— **全是附加功能**。

### 2.2 各引擎的可执行文件路径（**照抄，否则装好的引擎找不到**）

上游全部硬编码 `~/Library/Application Support/xenolauncher/modules/<引擎>/deps/…`。

```
nwjs:     deps/version/<version>/nwjs-sdk-<version>-osx-<arch>/nwjs.app/Contents/MacOS/nwjs
mkxpz:    deps/mkxpz/Z-Universal.app/Contents/MacOS/Z-Universal
easyrpg:  deps/player/EasyRPG Player.app/Contents/MacOS/EasyRPG Player
renpy:    deps/<…>/renpy-<x.y.z>-sdk/renpy.sh    ← 会扫目录找最新版，也支持 deps/renpy.sh 直放
```

> ⚠️ nwjs 的 `<arch>` 是 `os.arch()`（`arm64` / `x64`），**不是** `process.arch` 的 `x64`。

### 2.3 各引擎的启动命令

```js
// nwjs
`"<nwjsPath>" "<gameFolder>"`

// mkxpz：先把配置写进 Z-Universal.app/Contents/Game/mkxp.json，再启动（**无参数**）
`"<mkxpzPath>"`
// mkxp.json 内容：{ gameFolder, RTP: [...], rgssVersion: N, ...其余 gameArgs }

// easyrpg
`"<playerExec>" [--soundfont-path <sf2>] --window --project-path "<gameFolder>"`

// renpy
`"<renpyPath>" --savedir "<存档目录>/<gameName>" "<gameFolder>" [<command>]`
```

### 2.4 mkxpz 的 RTP 推断，**我们已有等价实现**

上游 `getRtpValue()`：读 `Game.ini` 的 `RTP=` → 扫 `System/RGSS*.dll` 推断。
**我们 M3 的 `diagnose.ts` 里已有**：`decideWantedRtp()` + `normalizeRtpName()`。

**直接复用，不用重写。**

## 3. 架构：新增 `src/main/launchers/`

### 3.1 结构

```
src/main/launchers/
├── index.ts        ← 入口：buildLaunchCommand(engine, ctx) → { binary, args, cwd, prelude }
├── binary-paths.ts ← ★ 所有引擎的可执行文件路径（**唯一来源**，R4）
├── nwjs.ts
├── mkxpz.ts
├── easyrpg.ts
└── renpy.ts
```

### 3.2 统一接口

```ts
export interface LaunchContext {
  /** 游戏根目录（已解析成绝对路径）。 */
  folder: string
  /** 用户的原始 gamePath（可能是文件夹里的某个 exe）。 */
  gamePath: string
  /** 引擎参数（已经过 reconcileVersionArgs）。 */
  gameArgs: Record<string, unknown>
  /** 游戏标题（renpy 拿它当存档目录名）。 */
  gameTitle: string
  /** 数据目录（引擎模块所在处）。 */
  dataDir: string
  platform: NodeJS.Platform
  arch: string
}

export interface LaunchPlan {
  /** 要执行的二进制绝对路径。 */
  binary: string
  /** 参数数组（**不要拼成字符串**——自己 spawn 要 argv 形式，天然免转义问题）。 */
  args: string[]
  /** 工作目录。 */
  cwd?: string
  /**
   * 启动**前**要做的事（写配置文件等）。
   * 返回 void；抛错 = 启动前置失败，**游戏不会被拉起**。
   */
  prepare?: () => void | Promise<void>
}

/** 不认识的引擎返回 null（调用方决定怎么处理）。 */
export function buildLaunchPlan(engine: string, ctx: LaunchContext): LaunchPlan | null
```

**为什么用 `args: string[]` 而不是拼命令行字符串**：
- `spawn(binary, args)` 天然处理空格/中文/引号，不用自己写 `quote()`
- 上游那些 `quote()` 函数就是在补这个坑

### 3.3 各引擎实现要点

#### nwjs（最复杂，但必需逻辑仍很少）

```ts
export function nwjsPlan(ctx: LaunchContext): LaunchPlan {
  const version = String(ctx.gameArgs.version ?? '')
  const binary = nwjsBinaryPath(ctx.dataDir, version, ctx.arch)
  // ⚠️ 不做：copyCheatFiles / modifyMainJs / applyProtection / chromium-args 篡改
  return { binary, args: [ctx.folder], prepare: checkBinaryExists(binary) }
}
```

**注意**：上游改了 `package.json` 的 `chromium-args`。我们**不改**——
待实测确认：不改会不会影响游戏运行（见 §8 R2）。

#### mkxpz

```ts
export function mkxpzPlan(ctx: LaunchContext): LaunchPlan {
  const binary = mkxpzBinaryPath(ctx.dataDir)
  const gameDir = path.join(path.dirname(path.dirname(path.dirname(binary))), 'Game')
  return {
    binary,
    args: [],
    prepare() {
      // 复用 diagnose.ts 的推断 + 上游的 passthrough 语义
      const { rtp, rgssVersion } = resolveRtpFor(ctx.folder, ctx.gameArgs)
      const config = { gameFolder: ctx.folder, RTP: rtpArray, rgssVersion, ...passthrough }
      fs.mkdirSync(gameDir, { recursive: true })
      fs.writeFileSync(path.join(gameDir, 'mkxp.json'), JSON.stringify(config, null, 4))
    }
  }
}
```

#### easyrpg / renpy

直接照上游拼（参数简单），见 §2.3。

### 4.1 `launch()` 重写后的形状

```ts
const plan = buildLaunchPlan(game.gameEngine, { folder, gamePath, gameArgs, gameTitle, dataDir, platform, arch })
if (!plan) throw failure('error.launchUnsupported', `引擎 ${engine} 暂不支持自实现启动`)

// 前置（写配置文件等）失败 = 不启动
await plan.prepare?.()

// macOS quarantine（保留）
if (platform === 'darwin') void runFile('/usr/bin/xattr', ['-dr', 'com.apple.quarantine', folder])

const child = spawn(plan.binary, plan.args, { cwd: plan.cwd ?? folder, detached: true, stdio: 'ignore' })
// ↑ detached + stdio:'ignore' = 游戏独立活下去，Tsumigeya 退出也不带走它
child.unref()

registry.addFromChild(id, child, engine, plan.binary)   // 直接有 pid
```

**`detached: true` 很重要**：否则关掉 Tsumigeya 会把游戏一起杀掉。

## 7. 风险

| # | 风险 | 处置 |
|---|---|---|
| **R1** | 自己拼的路径与上游不一致（装好的引擎找不到） | **照抄 §2.2 的拼法**；单测钉死；生产失配时报可读错误（含期望路径） |
| **R2** | 不篡改 `package.json` 的 `chromium-args` 是否影响游戏运行 | **必须真机对比**：同一游戏用上游启动 vs 自实现启动，看行为差异。若无差异就不改；若有差异，评估是否加那一个参数 |
| **R3** | NW.js 可能有子进程树，一个 PID 杀不干净 | M3.5 §9 R4 已记；自实现后可考虑 `detached` 起新进程组，用 `process.kill(-pid)` 整组杀 |
| **R4** | 上游未来改了 binary 路径 | 路径拼法**集中在一个文件**（`binary-paths.ts`），只改一处 |
| **R5** | 用户已装引擎在旧数据目录（若切目录） | 见 §5；默认选 A（不切），零风险 |
| **R6** | `spawn` 失败（ENOENT / EACCES） | 直接抛 `error.launchFailed` + 带上 binary 路径；**比上游的静默 console.error 好** |

## 8. 新增决策

| # | 决策 | 理由 |
|---|---|---|
| **D53** | **自实现启动，不用上游 `launcher.js`**；`module.js` 保留 | 上游 99% 是附加功能（含**改写用户游戏文件**）；自实现后默认不碰游戏目录 |
| **D54** | 用 **`spawn(binary, args[])`** 而不是拼命令行字符串 + `exec` | `args` 数组天然处理空格/中文/引号，不用自己写 `quote()`（那正是上游在补的坑）；且 `spawn` 直接给 `ChildProcess`（M3.5 的注入方案随之作废） |
| **D55** | 用 `detached: true` + `stdio: 'ignore'` + `child.unref()` | 否则**关掉 Tsumigeya 会把游戏一起杀掉**；游戏应该独立存活 |
| **D56** | 所有引擎可执行文件路径**集中在 `launchers/binary-paths.ts`** | 上游改了路径时只改一处；也便于单测覆盖 4 个引擎 × 2 个架构 |

### 10-③ 的重要说明：**未知引擎回退上游**

如果将来用户装了第三方模块（我们没实现启动的引擎），
`buildLaunchPlan` 返回 null → **回退到上游 `loadScript('launcher.js')`**。

这样：
- ✅ 4 个已知引擎走新路径（干净、有 PID、不改游戏文件）
- ✅ 未知引擎仍能启动（走老路径，有 `exec-inject` 就追踪、没有就没有）

**但注意**：这意味着 **`exec-inject.ts` 不能完全删**，要留作回退路径。

> 如果确认「只支持这 4 个引擎」，才能彻底删掉。**这是个需要用户拍板的取舍。**
