## 2. 为什么不做 Jellyfin 的 2:3 竖版海报

**用户已拍板选 4:3，但理由要留档**：

| 事实 | 说明 |
|---|---|
| DLsite 封面源图是 **4:3 横向** | 实测 `naturalWidth=560`，实际约 560×420 |
| Jellyfin 用 2:3 竖版海报 | 因为它的源图（电影海报）本来就是竖的 |
| 强行套 2:3 的后果 | `object-fit: cover` 会把横向图**左右各裁约 40%**，常切掉人物或标题文字 |

**结论**：形状跟随源图比例。卡片内部用**信息密度**（简介、标签、元信息）去贴近「海报墙」的观感，
而不是靠改变宽高比。

### 3.3 `og:description` 需要清洗

实测内容尾巴是站点广告：

```
「…」おま○こ当番とは、…。\n「DLsite 同人 - R18」は同人誌・同人ゲーム・同人ボイス・ASMRの
ダウンロードショップ。お気に入りの作品をすぐダウンロードできてすぐ楽しめる！毎日更新しているので
あなたが探している作品にきっと出会えます。国内最大級の二次元総合ダウンロードショップ「DLsite」！
```

**必须剥离**：从 `「DLsite` 或 `DLsite 同人` 开始到结尾的部分（站点自述）。
规则：截断在第一个 `「DLsite` 之前；清洗后为空则视为无简介。

**实测验证**（RJ294126，用上面规则）：260 字 → **122 字**，正好剥掉「「DLsite 同人 - R18」は同人誌…」之后的站点自述。

清洗实现建议（截断点按顺序找，取最靠前的）：

```ts
const SITE_TAIL_MARKERS = ['「DLsite', 'DLsite 同人', '国内最大級の二次元']
export function cleanupDescription(raw?: string): string | undefined {
  if (!raw) return undefined
  let cut = raw.length
  for (const mk of SITE_TAIL_MARKERS) {
    const i = raw.indexOf(mk)
    if (i >= 0 && i < cut) cut = i
  }
  const cleaned = raw.slice(0, cut).trim()
  return cleaned || undefined
}
```

## 10. 新增决策（**D39–D41**）

> ⚠️ 本方案初稿写的是 D36–D38，但**这三个编号已被 M3 实际占用**（`launch` 返回联合类型 /

> 编号是引用锚点，错位会让后续会话按错的决策做事，所以这里必须改。

| # | 决策 | 理由 |
|---|---|---|
| **D39**（原 D36） | 卡片封面**保持 4:3 横版**，不套 Jellyfin 的 2:3 竖版 | DLsite 源图是横向；2:3 会裁掉左右各约 40%，常切掉人物或标题。用户拍板 |

| **D41**（原 D38） | 启动按钮**只在详情页**，卡片上仅三点菜单 | 用户明确要求；卡片点击 = 查看详情，避免误点启动 |

| # | 决策 | 理由 |
