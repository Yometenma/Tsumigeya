## 2. P1：`An object could not be cloned.`（已修）

### 2.1 根因

`GameEditPage.save()` 把 `gameArgs` 直接传给 `saveGame`：

```ts
await library.saveGame(gameId.value, {
  gameTitle: title.value.trim(),   // 原始值，没事
  gamePath: path.value.trim(),     // 原始值，没事
  gameEngine: engine.value,        // 原始值，没事
  iconPath: iconPath.value,        // 原始值，没事
  tags: tags.value.filter(...),    // 新数组，元素是原始值，没事
  gameArgs: gameArgs.value         // ❌ reactive 对象，炸在这
})
```

`gameArgs` 是 `ref<Record<string, unknown>>`，而 `DynamicArgsForm` 往里写的是**嵌套 reactive 对象**。
contextBridge 用 **structured clone**，Proxy 过不去。

### 2.2 **为什么同一个坑踩了第二次**

M2.5 已经踩过一次（`saveGameMeta` 传 DLsite 元数据），当时的修法是**手写逐字段**的 `plainWork()`：

```ts
function plainWork(meta: DlsiteWork): DlsiteWork {
  return { rj: meta.rj, title: meta.title, /* …逐字段… */ }
}
```

**它只覆盖了「DLsite 元数据」那一条路径。** 这次是「基本信息」另一条路径，没人记得再套一次。

> **教训**：逐字段的防御性拷贝天生会漏——每加一条新路径就漏一次。

### 2.3 修法（结构性，不是补丁）

**`src/shared/plain.ts`**：通用 `toPlain()`，递归剥 Proxy：

| 输入 | 处理 |
|---|---|
| 对象 / 数组 | 递归展开成普通值 |
| 嵌套 Proxy | 逐层剥（浅拷贝救不了深层） |
| `Date` | 转 ISO 字符串 |
| 函数 | 丢弃（IPC 参数里不该有） |
| 循环引用 | 切断（WeakSet），不死循环 |
| 基本类型 | 原样返回 |

**在 store 层统一使用**（`src/renderer/src/stores/library.ts`）：

```ts
async function saveGame(id, draft) {
  const snapshot = await api.saveGame(id, toPlain(draft))   // ← 统一剥
}
async function saveGameMeta(gameId, work, editedFields) {
  const snapshot = await api.saveGameMeta(gameId, { work: toPlain(work), editedFields })
}
```

**为什么放 store 而不是页面**：页面/组件不用记得叫它，只要走 store 就一定被剥干净。
新加一条 IPC 路径也不会漏。

### 2.4 验证

**单测**（`test/plain-bridge.test.ts`，10 条）——其中两条**直接钉死这个 bug**：

```ts
expect(() => structuredClone(reactive draft)).toThrow()            // 证明 bug 真实存在
expect(() => structuredClone(toPlain(reactive draft))).not.toThrow() // 修完不抛
```

其余覆盖：`ref`/`computed`、数组里的 Proxy、函数丢弃、Date、循环引用、空 `gameArgs`、基本类型不误伤。

**端到端**（`scripts/probe-save-fix.cjs`，两阶段 `seed` → `check`）：

| 断言 | 结果 |
|---|---|
| 真点输入框改标题 → 真点「保存」 | ✅ 「保存测试」→「保存测试-改过了」 |
| `clonedErrors` | ✅ `[]` |
| 编辑页 `htmlLen` | ✅ 6888（不白屏） |

> ⚠️ 探针第一版**误判**成「编辑页白屏」，其实是它自己没刷新 store——
> 直接 `invoke('saveGame')` 不会更新 pinia，库页一直显示「共 0 个游戏」，编辑页判「游戏不存在」。
> 改成两阶段（seed 一个进程、check 另一个进程）才对。这个坑与 M2.6 探针的 `location.reload()` 同源。

## 3. P2 + P3：图标与标签

### 3.1 编辑页结构调整

**改前**（9 个区块，图标与标签散落在「基本信息」里）：

```
基本信息: 标题 / 路径 / 引擎 / 标签 / 图标
引擎参数
启动诊断
DLsite 信息
```

**改后**：

```
基本信息:   标题（带来源提示）/ 路径 / 引擎
封面与标签: 封面预览 / 标签 / 图标（折叠，标为「高级」）
引擎参数
启动诊断
DLsite 信息
```

### 3.2 封面预览：把「图标」与「封面」两个概念合并

用户看到的问题：编辑页里「图标」和「DLsite 封面」是两个独立区块，但**卡片只显示一个**。
现在合并成「封面预览」，显示**最终生效的那张**，并说明来源：

| `coverSource` | 显示 | 说明文案 |
|---|---|---|
| `dlsite` | DLsite 封面 | 「来自 DLsite 封面」 |
| `icon` | 本地图标（40×40 → 预览用 160×?) | 「来自本地图标（没有 DLsite 封面）」 |
| `placeholder` | 首字母 | 「没有封面也没有图标，显示首字母」 |

优先级与 `shared/gamecard-info.ts`、`GameCard.vue` **完全一致**（DLsite 封面 → 本地图标 → 首字母）。

### 3.3 图标折叠（不是删除）

```
▸ 图标（高级）
   卡片优先用封面，图标只在没有 DLsite 封面时作为兜底显示
```

- 默认**收起**（`iconSectionOpen = ref(false)`）——不占主界面
- 点开才出现「更改图标 / 清除图标」
- **保留手动改**（用户拍板：部分游戏封面不准）

### 3.4 标签：**保留**

**关键事实**（D40 / D19 已实测）：**DLsite 的标签拿不到**——
`work_genre` 区块在详情页与搜索结果页都是空的，靠额外 AJAX，返回 `[]`。

所以自定义标签是**唯一的标签来源**，不能删。但补了说明：
> 「DLsite 不提供分类标签，这里的标签是你自己的整理」

## 4. P4：游戏标题由 DLsite 接管

### 4.1 数据现实

```
GameRecord.gameTitle   → games.json        （上游 schema，D10 不改）
DlsiteWork.title       → library-meta.json （旁挂）
```

两份数据。M2.5 已有 `editedFields` 机制：用户手动改过 `title` 就标记，刷新不覆盖。

### 4.2 实现：只做「提示 + 快捷」，不动存储

| 元素 | 作用 |
|---|---|
| **来源提示**（标题下方小字） | 三种状态见下表 |
| **「用 DLsite 标题」按钮** | 有 DLsite 标题且当前不是它时出现，一点就填 |

| `titleSource` | 条件 | 提示文案 |
|---|---|---|
| `manual` | `editedFields` 含 `title` | 「当前使用你手动修改的标题（DLsite 标题不会覆盖它）」 |
| `dlsite` | 没改过 且 有 DLsite 标题 | 「当前使用 DLsite 标题」 |
| `dirname` | 没有 DLsite 元数据 | 「尚未获取 DLsite 信息，当前使用目录名/你填写的标题」 |

**为什么不做「自动改名」**：改 `gameTitle` 会写进 `games.json`（上游 schema）。
如果 DLsite 那边标题变了，我们的自动改名会让上游工具读到不同的值。
**显示层回落**更安全，且 M2.6 的卡片/详情页本来就有回落逻辑。

## 7. 新增决策

| # | 决策 | 理由 |
|---|---|---|
| **D44** | 过 contextBridge 的响应式数据**一律走通用 `toPlain()`**，且**在 store 层统一施加**，不做逐字段拷贝 | 逐字段方案踩了两次（M2.5 的 `plainWork` 只覆盖元数据路径，本轮基本信息路径又漏）。放 store 层 = 新加路径也不会漏 |
| **D45** | 图标**不删除，折叠为「高级」**；封面与图标合并成一个「封面预览」区块 | 图标在没有 DLsite 信息时是唯一兜底（用户拍板「保留手动改」）；合并是为了让用户看清「卡片到底显示哪张」 |

| **D47** | 标签**必须保留**，并在 UI 上说明「DLsite 不提供」 | D19/D40 已实测 DLsite 拿不到 genre；删了标签就没有任何标签来源 |

## 8. 探针踩的坑（留给下一个会话）

**「直接 invoke 不会刷新 pinia」**——探针里 `window.tsumi.invoke('saveGame', ...)` 只写盘，
库 store 的内存状态不变，于是：
- 库页显示「共 0 个游戏」
- 编辑页判「游戏不存在」

**本鱼第一版就误判成「编辑页白屏」**，白查了一轮。
正解：**两阶段**（一个进程 seed，另一个进程 check，让页面挂载时自然加载）。
`location.reload()` 不行——会把探针自己清掉（M2.6 探针踩过同样的）。

**断言 DOM 前先确认「数据真的在」**：`snapshot` 里能看到那条游戏，才说明页面该渲染它。
