# M5.5 实施方案：动态图标（Morphicons）

> **状态：已实施（v0.5.4 之后，未发布）**。M5.0 完成后实施（用户 2026-11-05：「先等 5.0 干完」）。
> §1–§8 是实施前的调研与计划（保留原样，便于对照"计划 vs 实际"）；
> **§9 是实施结果与偏差记录**——实际做法有几处和原计划不同，理由都写在那里。

---

## 1. 用户需求

> 「https://www.morphicons.com/ 我找到开源的动态按钮图标库，到时候接入吧，先等 5.0 干完」

**要的是**：按钮 / 图标有「动态感」——状态切换时图标平滑变形，而不是硬切。

---

## 2. Morphicons 核实结果（已查证）

| 项 | 情况 |
|---|---|
| **许可** | **MIT** —— 商用、修改、再分发都行，不要求我们的代码开源 |
| **体积** | gzip **10 KB**，**零运行时依赖** |
| **框架** | React / **Vue** / Svelte / React Native / Astro + vanilla JS |
| **原理** | 纯 SVG 路径变形（morph），**闭式**求解旋转/缩放/位移，无配置 |
| **性能** | 屏幕所有图标共享 **1 个 rAF** |
| **图标源** | Lucide / Tabler / Heroicons / Iconoir / Material Symbols / Phosphor / Hugeicons / shadcn |
| **输入格式** | **SVG `d` 属性** 或 **Lucide 的 `IconNode`** —— 图标是**数据**不是组件 |

官方示例（Vue 同构）：

```tsx
import { MorphIcon } from "morphicons/vue"
import { Menu, X } from "lucide"   // 数据，不是组件

<button onClick={() => setOpen(o => !o)} aria-expanded={open}>
  <MorphIcon icon={open ? X : Menu} />
</button>
```

**"That is the whole thing. No wrappers, keys or configuration."**（官方原话）

| 问题 | 决定 |
|---|---|
| **图标体系** | ✅ **换成 Lucide**（Element Plus 图标全换掉） |
| **接入时机** | ✅ **M5.0 之后**（M5.5） |

## 4. 现状盘点（为什么接入成本很低）

### 4.1 Element Plus 图标的实际用量

```
只有 2 个文件、5 个图标：
  components/GameCard.vue:16     MoreFilled
  pages/GameDetailPage.vue:19    ArrowLeft, Top, Bottom, Refresh
```

### 4.2 侧边栏导航用的是 **emoji**，不是 SVG

```ts
// App.vue:26-28
{ path: '/library',  label: t('nav.library'),  icon: '🎮' },
{ path: '/engines',  label: t('nav.engines'),  icon: '⚙️' },
{ path: '/settings', label: t('nav.settings'), icon: '🛠️' }
```

**emoji 的问题**：跨平台渲染不一致（mac 上是彩色 emoji，和暗色 UI 不搭）、无法做 morph、无法控制粗细。

**换成 Lucide 顺带解决这个体验问题** —— 这是额外收益。

### 4.3 依赖现状

```json
"@element-plus/icons-vue": "^2.3.2"    // 只有那 5 个图标在用
```

## 5. 适用 / 不适用场景

### ✅ 适合 morph 的（状态切换型）

| 位置 | 变形 |
|---|---|
| 侧边栏折叠 | `Menu` ←→ `X` |
| 游戏运行中 | `Play` ←→ `Pause`（或 `Square` 停止） |
| 引擎页「检查更新」 | `RefreshCw` 旋转（不是 morph，是 rotate） |
| 详情页展开/收起简介 | `ChevronDown` ←→ `ChevronUp` |
| 批量模式开关 | `ListChecks` ←→ `X` |
| 分类筛选 | `Folder` ←→ `FolderOpen` |
| 已保存状态 | `Save` → `Check` |

### ❌ 不适合的（一次性动作）

- 「添加游戏」按钮 —— 点一下就是点一下，没有「两种状态」
- 「删除」—— 稀缺动作，变形没有信息价值
- 纯装饰图标（封面占位、空状态插画）

**原则**：**只在「同一个按钮有两种状态」的地方用 morph**。硬塞到所有按钮上是滥用。

## 6. 实施计划（M5.0 完成后）

### S1 引入依赖

```bash
npm i morphicons lucide
npm uninstall @element-plus/icons-vue
```

**注意**：Lucide 要装「图标数据」部分，不是 React 组件包
（`lucide` 这个名字可能不对，实施时核实；官方示例的 import 是 `from "lucide"`）。

### S2 替换 5 个现有图标

| 文件 | 原 | 新（Lucide） |
|---|---|---|
| `GameCard.vue` | `MoreFilled` | `Ellipsis` |
| `GameDetailPage.vue` | `ArrowLeft` | `ArrowLeft` |
| | `Top` | `ChevronUp` / `ArrowUp` |
| | `Bottom` | `ChevronDown` / `ArrowDown` |
| | `Refresh` | `RefreshCw` |

### S3 侧边栏 emoji → Lucide 图标

```ts
{ path: '/library',  icon: Gamepad2 }
{ path: '/engines',  icon: Settings }
{ path: '/settings', icon: Wrench }
```

**渲染方式**：`App.vue` 的 `<span>{{ item.icon }}</span>` 要改成组件渲染。

⚠️ **模板禁 TS 断言**（AGENTS.md 已知坑）—— 图标组件要作为数据传进去，
在 `<script setup>` 里处理，不要在模板里写类型。

### S4 加 morph（按第 5 节的清单，从最有价值的开始）

**优先级**：
1. 侧边栏折叠 `Menu` ←→ `X`（最明显）
2. 游戏运行状态 `Play` ←→ `Square`
3. 展开/收起 `ChevronDown` ←→ `ChevronUp`

### S5 验收

- 本机能验：图标渲染正确、切换不报错、无 console 错误
- **要用户验**：动效手感（速度、弹性）、暗色下的粗细是否合适

## 9. 实施结果（实际做了什么 / 与原计划的偏差）

> 本节是「现在是什么」。上一节（§7）的待确认项在这里都有了答案。

### 9.1 实施顺序对照

| 步 | 计划 | 实际 | 备注 |
|---|---|---|---|
| S1 | `npm i morphicons lucide`；卸 `@element-plus/icons-vue` | ✅ `morphicons@2.0.2` + `lucide-vue-next@1.0.0`（**不是 `lucide`**）；`@element-plus/icons-vue` 从 package.json 移除 | 见 9.2 |
| S2 | 替换 5 个 Element 图标 | ✅ 5 个全换（MoreFilled→Ellipsis、ArrowLeft→ArrowLeft、Top/Bottom→ChevronUp/Down、Refresh→RefreshCw） | 详情页的 Top/Bottom **不只是换图标**，见 9.4 |
| S3 | 侧边栏 emoji → Lucide | ✅ Gamepad2 / Settings / Wrench | 与计划一致 |
| S4 | 加 3 处 morph | ✅ 三处全做 | ① 需要**新建**折叠功能，见 9.3 |
| S5 | 验收 | ✅ 三绿 + 探针实测；手感待用户真机确认 | 见 9.6 / 9.7 |

### 9.2 包名更正（计划 §7 待确认项 1/5 的答案）

计划写的是 `npm i morphicons lucide`，**实际装 `lucide-vue-next`**：

- `lucide`（数据包）的图标是 `[tag, attrs][]` 数组，**没有 `.d` 访问器**，是给 vanilla JS 的
- `lucide-vue-next` 是 Vue 的非组件包，导出的是**函数式组件**，几何在闭包里
- `@element-plus/icons-vue` 卸掉后**无连带影响**：它仍作为 `element-plus` 的传递依赖存在
  （Element Plus 自己的 loading / 消息图标要用），只是不再出现在**我们的** package.json 里

⚠️ **镜像源陷阱**：`npm i lucide-vue-next` 从 npmmirror 拉到的是 **0.577.0**（旧版），
而 npm 官方 `latest` 是 **1.0.0**。两者几何**完全一致**（已逐条比对），但版本要钉死：
本仓库固定 `^1.0.0`。

### 9.3 S4-① 侧边栏折叠：**这个功能原本不存在**（必须新建）

计划 §5/§6 把「侧边栏折叠 Menu←→X」列为最高优先级，但实施时发现：

> **App.vue 从来没有折叠态** —— 固定 `--tsmg-sidebar-width: 208px`，
> 没有开关、没有折叠 CSS、没有状态。

所以 S4-① 实际是**新增功能**，不能只算"加个 morph"。新建了：

- `src/shared/sidebar-collapse.ts`（判据：宽度、哪些块折叠时收起、无障碍标签方向）
- `src/renderer/src/components/SidebarToggle.vue`（按钮本身，两个位置复用同一份）
- App.vue 的折叠状态（**只在内存**，不落盘：临时的视图选择不该假装成持久偏好，D50 同一取向）

**核心判据**（`sidebar-collapse.ts`）：折叠时哪些块必须收起。漏一个的表现是
「分类名/计数/新建分类溢出或被裁」，而**页面照常渲染、不报错** —— 所以写成数据清洁单核对
「每个侧边栏块恰好归到显示/隐藏一边」，12 条单测守着。

### 9.4 两处 morph 的**真问题**：图标必须活到状态改变那一刻

这是本轮技术含量最高的一点，两次都踩了同一个坑：

**坑的形态**：`v-if` / `v-else` 两个容器各放一个图标（或按钮），状态一变就**销毁旧的、新建新的**。
MorphIcon 的变形靠「同一个实例里 `icon` prop 换成新引用」，实例都没了 → 用户只看到**生硬的替换**
（正是要消灭的那个闪烁），而且**不报错、不警告**。

| 位置 | 原写法 | 改成 | 探针实测 |
|---|---|---|---|
| 侧边栏折叠按钮 | 品牌行 `v-if` / 折叠行 `v-else`，各放一个 SidebarToggle | 外层 div 永远在，只换 class + 文字 `v-if` | 改前 `d` 属性**没变**（morph 静默失效）；改后 `dChanged=true` |
| 详情页启动/停止 | 两个 `<el-button>`，`v-if`/`v-else` | **合成一个** button，`:type`/`:size` 随态变，`@click` 分发 | 改后 10/10 采样帧在中途 |

### 9.5 图标几何的唯一来源：手抄常量 + 漂移测试

`lucide-vue-next` 只导出**组件**，而 morphicons 要**数据**（`IconNode`）。三种取法：

1. 从组件里抠（`component({}, {slots:{}}).props.iconNode`）—— **能work**，但赌 lucide 内部实现细节：
   它换个写法就静默 `undefined` → `MorphIcon icon={undefined}` **只是不画，不报错**（白屏级故障）
2. 从 `lucide`（数据包）取 —— 要装第二个几百 KB 的包，且版本分裂风险
3. **手抄常量**进 `src/shared/icon-nodes.ts` + **与包内真实数据逐字节比对的单测**

选了 ③。生产代码只依赖 lucide 导出的**名字**（不依赖内部结构）；
包一升级、几何一变，`test/icon-nodes.test.ts` 当场变红并给出「该抄成什么」。

> 这条判据**反向验证过**：本鱼第一版抄错了 `Gamepad2` 与 `Settings` 两个路径，
> 被它抓出来了（`❌ Gamepad2: 期望 … 实际 …`）。没有它，这两个图标会**悄悄变丑**。

### 9.6 §7 待确认项：全部有了答案

| # | 问题 | 结论 |
|---|---|---|
| 1 | 弹簧速度/弹性 | **无回弹**（用户拍板），但**不用官方 `smooth`**：实测 0.72s 太慢，面板都收完了图标还在飞。改用显式 `{stiffness:400, damping:40}`（仍是 ζ=1 零回弹）→ **0.48s**。实测表见 `AppIcon.vue` 注释 |
| 2 | 图标粗细 stroke | **1.5**（暗色 UI 上更精致）。**要用户真机确认**（见 9.7） |
| 3 | 按需引入 | ✅ 只定义 + 使用 12 个图标；`region`（填充图标归一化，24.8 KB）是**动态 import**，只用描线图标 → 永不加载 |
| 4 | 卸载 icons-vue 的连带影响 | ✅ 无。仍是 element-plus 传递依赖 |
| 5 | `lucide` 全量还是按需 | 见 9.2（用 `lucide-vue-next`），且只取 12 个名字 |

### 9.7 本机已验 vs 要用户验

**本机已验（真跑 Electron + 读 DOM，非静态检查）**：

- 侧边栏：3 个导航图标渲染正确、emoji 无残留、折叠 208→56px、
  分类区与导航文字确实收起、`aria-expanded` 正确翻转、**再点回来可逆**
- 折叠图标 morph：`d` 逐帧变化（12/12 采样帧在中途，非硬切），**落回干净的规范 `d`**
- 详情页简介折叠：`ChevronDown`→`ChevronUp`，8/8 帧在中途
- 详情页启动按钮：`Play` 形态、`strokeWidth=1.5`、`size=18`；
  发一条真实 `gameStarted` 事件 → morph 到 Square（10/10 帧在中途）、文案变「关闭游戏」
- **console 零错误**

**要用户真机确认（本鱼不声称已验收）**：

- **动效手感**：0.48s 快慢是否合适、阻尼是否够稳（`AppIcon.vue` 的 `SPRING` 两个数字可直接调）
- **暗色下粗细**：1.5 是否偏细（`AppIcon.vue` 的 `strokeWidth` 默认值）
- **折叠面板与图标节奏是否协调**：宽度过渡 0.42s vs 图标 0.48s，主观感受

### 9.8 新增测试（+33 条 / +2 文件）

| 文件 | 条数 | 守什么 |
|---|---|---|
| `test/icon-nodes.test.ts` | 21 | 手抄几何与 lucide 包逐字节一致；morph 配对合法性（两端点不同/不重不漏归类） |
| `test/sidebar-collapse.test.ts` | 12 | 折叠时哪些块收起（不重不漏）；宽度；无障碍标签方向 |

### 9.9 已知遗留

- `lucide-vue-next` 的 `IconNode` 类型是**可变** `[string, Record<string,string>][]`，
  我们的（沿用 morphicons）是 `readonly` + attrs 允许 number。运行时完全兼容，
  `AppIcon.vue` 里有一次浅拷贝做类型对齐（**不改变几何**）。
- 侧边栏折叠态**不持久化**（有意为之，见 9.3）。若用户要求记住，需要进 `Settings`
  （那会触发 `settings-groups.ts` 的「每个字段恰好归一次」测试，属于独立的小改动）。
