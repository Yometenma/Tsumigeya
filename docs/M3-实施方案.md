## 1. 为什么做这件事

现在游戏跑不起来时，用户看到的是 mkxp-z 的英文报错：

```
No script file has been specified. Check the game's INI and try again.
```

**用户完全不知道该做什么**。M3 的目标是：让每一种失败都变成**可操作的中文提示**，
能一键修的给按钮，不能修的告诉用户去哪做什么。

## 2. 已实测确认的技术前提（**不要重复验证**）

### 2.1 RGSS 加密归档的魔数（**实测确认**）

```
RGSSAD\0\x01  → RPG Maker XP      (.rgssad)
RGSSAD\0\x02  → RPG Maker VX      (.rgss2a)
RGSSAD\0\x03  → RPG Maker VX Ace  (.rgss3a)   ← 用户真实的 傭兵の冒険 实测为 003
```

读法：读文件头 8 字节，前 7 字节是 `RGSSAD\0`，第 8 字节是版本号。

**用途**：`.rgss3a` 的存在本身就是**强信号**，可以直接判 RGSS 版本，
不用等 mkxp-z 去猜（launcher 的 `getRtpValue` 靠扫 `RGSS3xx.dll` 猜，不稳）。

### 2.2 用户真实样本（`E:\Game\RPG`，与 Mac 上一致）

| 游戏 | 结构 | 诊断结论 |
|---|---|---|
| `傭兵の冒険/傭兵の冒険_CHN` | `Game.exe` + `Game.ini` + **`Game.rgss3a`**（121MB）+ `Audio/` + `Fonts/` + `System/`，**无 `Data/` 目录** | 加密发行，`rgssVersion=3` |
| `Karryn's Prison` | NW.js（`nw.dll` + `package.json` + `www/`） | 正常 |
| `艾妮希雅…(Enishia…)` | MV/MZ（`data/*.json` + `nw.dll`） | 正常 |
| `Magical Girl Celesphonia` | NW.js | 正常 |
| `Unholy_maiden_Ver.1.0.10` | NW.js | 正常 |

**所以 §① 有一个现成的真实回归样本**，测试与验收都用它。

### 2.3 RTP 的真实结构（**实测确认**）

```
deps/RTP/RTP/RPGVX/        ← RPG Maker VX
deps/RTP/RTP/RPGVXAce/     ← RPG Maker VX Ace（真实目录名就是这个大小写）
deps/RTP/RTP/Standard/     ← RPG Maker XP
```

> ⚠️ **M4.0 S3 纠正（2026-11-04）**：初稿把 XP 写成 `RPGXP/` 并注明「推测」，**推测是错的**。
> 直接下载真实 `RTP.zip`（255,812,166 字节）读中央目录，其下**只有**这三个目录：
> `RTP/Standard/`、`RTP/RPGVX/`、`RTP/RPGVXAce/`。
>
> 后果：读不到 `Game.ini` 的 `RTP=` 时按版本映射 → 查 `deps/RTP/RTP/RPGXP` 永远不存在
> → **XP 游戏永久判「RTP 缺失」，一键补装也修不掉**。已改为 `Standard`，
> 并把 `RPGXP` 留作别名（游戏自己可能这么写）归一化到 `Standard`。

来源：`mkxpz` manifest 的 `dependencies.RTP` → `RTP.zip`（**255,812,166 字节 ≈ 244MB**），
内部顶层是 `RTP/<版本>/Audio|Graphics|...`。

**注意体积**：244MB，不是小包。所以 **RTP 只在确实缺失时才提示补装**，不要每次都拉。

### 2.4 `fontSub` 的语义（**与直觉不同，别搞错**）

### 2.5 `Game.ini` **不是 UTF-8**（实测，必须注意）

用真实样本 `傭兵の冒険_CHN/Game.ini` 实测：

```
Title=Ó¶±øµÄÃ°ÏÕ     ← 按 latin1 读出来的样子
hex : d3b6 b1f8 b5c4 c3b0 cfd5   ← 这是 GBK 编码的「傭兵の冒険」
```

**结论**：`Game.ini` 由 Windows 版 RPG Maker 生成，是 **GBK / Shift-JIS 等本地编码**，
按 UTF-8 读会把 `Title` 读成乱码。

**对策**：
- 我们只关心 **ASCII 结构行**（`[Game]` / `RTP=` / `Scripts=` / `Library=`），
  这些在 GBK 下也是 ASCII，按 `'latin1'` 或 `'binary'` 读即可正确解析
- **绝不要**用 `Title=` 的内容做任何判断或展示（会乱码）
- 若将来要做「从 ini 取游戏标题」，需要显式编码猜测，那不在 M3 范围

```jsonc
// mkxp.json 里的 fontSub 是「字体替换映射」，不是「字体目录加载器」
"fontSub": ["Arial>Open Sans", "Times New Roman>Liberation Serif"]
//          ↑ 「游戏要求 Arial」，就用 Open Sans 代替
```

而游戏自带的 `Fonts/*.ttf`（如 `傭兵の冒険` 里的 `Lolita.ttf`、`VL-Gothic-Regular.ttf`）
**mkxp-z 本来就会自动加载**。

**结论**：§③ 不能做「自动字体修复」——那需要猜用户遇到什么字体问题，猜错反而添乱。
**降级为「检测 + 提示」**（见 §5）。

## 3. 诊断模型（`src/main/diagnose.ts`，纯逻辑，**不 import electron**）

### 3.1 类型

```ts
export type DiagnosisLevel = 'fatal' | 'warning' | 'info'

export interface Diagnosis {
  /** 稳定标识，UI 与 i18n 用它查文案 */
  code: 'encryptedArchive' | 'missingRtp' | 'missingExecutable' | 'moduleMissing' | 'pathGone' | 'fontsPresent'
  level: DiagnosisLevel
  /** 给用户看的中文（i18n key，不是原文） */
  messageKey: string
  /** 文案里的占位符 */
  args?: Record<string, string>
  /** 能一键修的话，指向哪个修复动作；修不了就是 undefined */
  fix?: DiagnosisFix
}

export type DiagnosisFix =
  | { kind: 'installRtp'; engine: string }        // 触发 moduleTask(engine, 'dependencies')
  | { kind: 'installModule'; engine: string }     // 引擎未装
  | { kind: 'openFolder'; path: string }          // 让用户去看/整理目录
  | { kind: 'repoint'; }                          // 路径失效，去编辑页重选

/** fatal 会拦下启动；warning/info 只提示 */
export function isBlocking(d: Diagnosis): boolean
```

### 3.2 四个检测器

#### ① `detectEncryptedArchive(dir, fileName)`

```
条件：目录里有 *.rgss3a / *.rgss2a / *.rgssad
      且**没有** Data/Scripts.rvdata2（也没有 Data/Scripts.rvdata）
输出：Diagnosis{ code:'encryptedArchive', level:'fatal',
        messageKey:'diagnose.encryptedArchive',
        args:{ file:'Game.rgss3a', rgssVersion:'VX Ace' },
        fix:{ kind:'openFolder', path:dir } }
```

- 版本从魔数第 8 字节推断（§2.1）
- **检测不到的边界**：如果用户已经解包并放了 `Data/Scripts.rvdata2`，就不报这条（哪怕 `.rgss3a` 还在）

#### ② `detectMissingRtp(engineDir, wantedRtp)`

```
wantedRtp 来源：读 Game.ini 的 [Game] RTP= 行（大小写不敏感），如 "RPGVXace"
             读不到就按 rgssVersion 映射（1→RPGXP / 2→RPGVX / 3→RPGVXace）
检查：<modulesDir>/<engine>/deps/RTP/RTP/<wantedRtp> 是否存在且是目录
输出：缺失 → Diagnosis{ code:'missingRtp', level:'warning',
        args:{ rtp:wantedRtp, engine },
        fix:{ kind:'installRtp', engine } }
```

- **`warning` 不拦启动**：缺 RTP 的游戏可能仍能跑（只是缺素材），先让用户试
- 只对 `mkxpz` 这类 RGSS 引擎检查；NW.js/MV 不需要 RTP

#### ③ `detectMissingExecutable(dir)` / ④ `detectPathGone(gamePath)`

```
pathGone  : gamePath 不存在             → fatal + fix{kind:'repoint'}
moduleMissing: 引擎模块未安装           → fatal + fix{kind:'installModule'}
missingExecutable: 目录里找不到任何可执行候选 → fatal + fix{kind:'openFolder'}
```

#### ⑤ `detectFontsPresent(dir)`（info，**只提示不修**）

```
条件：目录存在 Fonts/ 或 fonts/ 且里面有 .ttf/.otf
输出：Diagnosis{ code:'fontsPresent', level:'info', args:{ count } }
```

文案：**「这个游戏自带 N 个字体文件。如果游戏内文字显示为方块/乱码，多半是字体没被正确加载」**——
只做提示，不做自动修复（理由见 §2.4）。

### 3.3 汇总函数

```ts
export function diagnoseGame(input: {
  game: { gamePath: string; gameEngine: string }
  modulesDir: string
  installedModules: string[]
}): Diagnosis[]
```

按 `fatal → warning → info` 排序返回。

## 4. IPC 与集成

### 4.1 新增命令（**沿用 `tsumi:invoke`，零新 channel**）

| 命令 | 参数 | 返回 | 队列 |
|---|---|---|---|
| `diagnoseGame` | `{ gameId }` | `Diagnosis[]` | **绕队列**（纯本地只读、毫秒级） |
| `repairGame` | `{ gameId, fix }` | `{ ok, message }` | 进队列（可能要装 244MB 的 RTP） |

`diagnoseGame` 加进 `OFF_QUEUE_METHODS`（`ipc.ts` 已抽成常量）。
`repairGame` **不进**——它可能触发长时间下载，必须排队。

### 4.2 启动前拦截（**用户选的方案**）

在 `ipc.ts` 的 `launch` 里，`launch` 之前插入：

```ts
const diagnoses = diagnoseGame(...)
const blocking = diagnoses.filter(isBlocking)
if (blocking.length) {
  // 返回结构化结果，让 UI 弹「诊断对话框」而不是抛英文错误
  return { blocked: true, diagnoses }   // ← launch 的返回类型要扩
}
```

**注意契约变更**：`launch` 现在返回 `{ message }`，要扩成 `{ message } | { blocked, diagnoses }`。
三处同步：`ipc.ts` / `api/client.ts` /（preload 不改，因为走 invoke）。

UI 侧：`library.ts` 的 `launch` 拿到 `blocked` 时弹 `ElMessageBox`：
- 标题「这个游戏暂时无法启动」
- 正文列诊断（每条一行图标 + 文案）
- 按钮：[取消] [一键修复]（有 fix 时）[还是启动试试]（仅 warning 时）

### 4.3 设置项（可选）

```ts
// 是否每次启动都诊断。默认 true。
diagnoseBeforeLaunch: boolean
```

用户如果嫌慢可以关（本机实测应当是毫秒级，但没有实测数据前不给承诺）。

## 10. 新增决策（D32–D35）

| # | 决策 | 理由 |
|---|---|---|
| **D32** | 诊断**只用本地文件特征**，不调 mkxp-z、不解析英文报错 | 报错信息不稳定且英文；本地特征（魔数、目录结构）是确定的 |
| **D33** | `.rgss3a`/`.rgss2a`/`.rgssad` 的魔数版本号**优先于** launcher 的 DLL 扫描推断 | 魔数是归档自身的声明，比扫 `RGSS3xx.dll` 可靠（用户可能删了 dll） |
| **D34** | **加密发行不自动解包**，只检测 + 提示 + 引导（延续 M3 路线图的既有拍板） | DRM 破解的法律风险；产品只负责告诉用户怎么做 |
| **D35** | `fontSub` **不做自动修复**，只做「自带字体存在」的提示 | 实测 `fontSub` 是字体**替换映射**（`"Arial>Open Sans"`），不是目录加载器；游戏自带 `Fonts/` 本就被自动加载。自动改会猜错反而添乱 |
