# M4.2 实施方案：删除 module.js（彻底零上游）

> **用户意图**（原话）：「做 m4.0 本来就是为了摆脱 xenolauncher 的依赖……
> 别给我小偷小摸偷偷藏着还有本来我们决定不要了的东西」
>
> 状态：**方案待实施**。基线：M1–M4.1 全绿（755 tests / 31 files），v0.4.1 已发布。

---

## 1. 现状

`resources/core/module.js`（**1911 行 / 73 KB**）仍在用，**18 个 API 被调用**。

M4.0 砍了启动（`launcher.js`），M4.1 砍了引擎清单（`manifest` 拉取），
但 module.js 本体没动 —— 这就是"偷偷藏着"的那部分。

**判定规则**（照抄上游语义，从 registry 的 `autodetect` 读）：

- `files`：列出的文件/目录**都在**才算（`all_required: true`）
- `extensions`：路径的扩展名命中任意一个
- `all_required: false`（easyrpg）→ 命中任意一个即可

> ⚠️ 这里有个历史坑：`isAppBundlePath` / `normalizeExt` / `gameDirForFiles` 处理
> `.app` 包与「文件在子目录里」的情况。**必须覆盖**，否则 mac 上的 .app 游戏识别不出来。

### 2.3 `semver.ts`

## 3. 唯一真正复杂的一块：多版本保留更新

**问题**：nwjs 的 deps 是 `deps/version/v0.106.1/`（每个版本一个目录）。更新模块时
**不能把旧版本删掉**，否则用户已装的其他版本 nwjs 游戏全坏。

**上游行为**（`updateModulePreservingMultiversionsWithProgress`，实测约 80 行）：
1. 读旧 manifest 的 `dependencies`
2. 识别哪些是 multi-version（名字含 `version/` 前缀）
3. 新建临时目录 → 装新 manifest 的非多版本依赖
4. **把旧的多版本目录整个 cp 过来**
5. 事务替换

**我们的实现**（简化，因为引擎只有 4 个）：

```ts
async function updateEngine(folder, signal, progress) {
  const old = readManifest(dataDir, folder)          // 旧
  const next = buildManifest(registryEngine)         // 新（registry 生成）
  // 1. 找出旧 manifest 里的多版本依赖（name 含 "version/"）
  const keep = Object.keys(old.dependencies ?? {}).filter((k) => k.includes('version/'))
  // 2. 清掉非多版本部分，装新的
  // 3. 把 keep 对应的 deps 子目录原样搬回来
  // 整个包在 moduleTransaction 里（外层已有）
}
```

**关键不变量（配测试）**：
- 更新后 `deps/version/v0.106.1/` **必须还在**（内容哈希不变）
- 更新后 `deps/mkxpz/` 是**新版本**
- manifest 里的 `dependencies` 键集与 registry 一致

## 6. 删掉的功能（要确认接受）

| 功能 | 为什么删 | 影响 |
|---|---|---|
| **检查依赖更新** | 没有远端清单可比较 | 引擎页少一个「依赖有更新」徽标 |
| **检查引擎更新** | 降级为「本地版本 vs registry 硬编码版本」 | 仍能提示「有新版本」，只是比较对象是自己写死的版本 |
| `deleteWithEngine`（postdelete 钩子） | 我们生成的 manifest 没这个文件，**现在就是空操作** | 删游戏不再多绕一步；反而修掉「钩子失败拦住删游戏」 |
| `.native-backups` 的 core 内部版本 | 我们的 `moduleTransaction` 已经做了同样的事 | 无 |

## 8. 新增决策

| # | 决策 | 理由 |
|---|---|---|
| **D63** | **删 `resources/core/module.js`**，18 个 API 全部自实现或删除；`FORK-NOTES.md` 保留作历史记录 | 用户明确要「彻底摆脱」。M4.0/M4.1 已砍掉一半，留着 1911 行上游代码等于半途而废 |
| **D64** | **「检查依赖更新」功能删除**；「检查引擎更新」降级为「本地 vs registry 版本」 | 不再有远端清单，依赖更新检查没有比较对象。留着只是空壳 |
| **D65** | `deleteWithEngine` **删除**，删游戏直接走 `store.removeGame` | 它调模块里的 `postdelete.js`，而我们生成的 manifest **不含该文件** → 现在等于空操作，且钩子抛错会拦住删游戏（是 bug） |
| **D66** | `updateEngine` 的多版本保留**用「识别 `version/` 前缀 + 原样搬回」**，不重写上游那套临时目录流转 | 引擎只有 4 个，多版本只有 nwjs 一种形态。简化实现 + 3 条不变量测试足够 |
