## 一句话总结

**引擎从 4 个扩到 9 个**，覆盖范围从「RPG Maker 全家 + Ren'Py」扩到
「RPG Maker 全家 + Ren'Py + 日本视觉小说主力引擎」。

⚠️ **其中 5 个是实验性支持，未在任何真实游戏上验证过** —— 详见下方「实验性支持」一节。
**这不是谦虚，是事实陈述**：请把它当「可以试试」，不要当「保证能玩」。

## 新增引擎（5 个）

| 引擎 | 运行时 | 许可证 | 典型作品 |
|---|---|---|---|
| **TyranoScript**（ティラノスクリプト） | 复用 NW.js（**零额外下载**） | — | 大量 HTML5 视觉小说 |
| **吉里吉里**（KiriKiri） | krkrsdl2 | MIT | 经典 VN |
| **NScripter** | ONScripter | GPL-2+ | 月姫 / ひぐらし / うみねこ 等 |
| **Siglus** | siglus_rs | MPL-2.0 | **一个引擎覆盖 UK2 / AVG32 / RealLive / SiglusEngine 四种格式** |
| **Godot** | 官方编辑器二进制（154 MB） | MIT | 仅 GDScript 项目 |

### 为什么是这 5 个

判据只有一条：**游戏资源是否跨平台 + 有没有能在 macOS 上自己实现的运行时**。

> 这条判据**不是**「DLsite 标没标支持 Mac」——
> 本启动器的存在理由恰恰是「作者只发 Windows 包，我们用自己装的 mac 运行时跑它的资源」。

按这条判据，Unity / RPG Bakin / ウディタ 不满足（只有 Windows 二进制），
所以**没有**做。它们会被**识别**出来并提示「需要 Windows 兼容层」，但不会代跑。

## ⚠️ 实验性支持（请务必读这一节）

引擎页会给这些引擎打标签，两种原因**分开显示**：

### 🔶「未验证」—— 我们没在真实游戏上验证过

**TyranoScript / NScripter / Siglus / Godot**

我们已经验证的：
- ✅ 识别规则（单测 + 真机界面）
- ✅ 启动命令构造（对照官方文档）
- ✅ 下载地址**实测可下载**（HTTP 206）
- ✅ 安装/启动过程**不修改你的游戏文件**

**我们没验证的：**
- ❌ **没有任何一款真实游戏被成功启动过**

也就是说：**命令是对的，但游戏能不能真的跑起来，我们没有证据。**
如果遇到问题，欢迎反馈 —— 这正是标这个标签的原因。

### 🟡「上游限制」—— 运行时作者明说某些用法不受支持

**吉里吉里**：krkrsdl2 官方页明确写着：

> "Running **unmodified commercial games** using this project is **not supported**."

它**技术上能用**（我们不会拦你），但出问题时这是上游的立场，不是本项目的承诺。

## 已知限制

### 存档管理

| 引擎 | 存档位置 |
|---|---|
| NW.js / mkxp-z / EasyRPG / Ren'Py | ✅ 已支持（v1.0.0 起） |
| NScripter | ✅ 支持（启动时显式指定 `--save`） |
| **TyranoScript / 吉里吉里 / Godot** | ❌ **未实现，显示「不知道在哪」** |

后三个**故意不猜**：宁可显示「不知道」让你去排障，也不猜一个错的路径
——猜错会让你看到别人的残留存档，那比「看不到」更糟。

### TyranoScript 的分发包形态

| 形态 | 支持 |
|---|---|
| v4 未打包（`tyrano/` + `data/` 在根） | ✅ |
| v5 unpacked（`resources/app/`） | ✅ |
| v5 packed（只有 `resources/app.asar`） | ❌ NW.js 原生不支持 asar |
| 单文件 exe（`exe` 尾部拼 zip） | ❌ 需要真实样本才能做 |

后两种会**明确报错并说明原因**，不会静默失败。

### Godot

- 只支持 **GDScript 项目**。C# 项目在 macOS 上加载不了（引擎限制）。
- 用了 **GDExtension** 的游戏也不支持（含平台专用动态库）。
- pck 必须与引擎**版本匹配**（4.6.x 的 pck 配 4.6.x 引擎）。
- **存档位置改不了**（官方明确导出工程不支持重定向）。

## 顺带修复的 bug

### 1. mac 上含中文/日文文件名的压缩包会被判「恶意」🔴

**这是个只在 macOS 上出现的真 bug，本机 Windows 测不出来。**

- **现象**：解压任何含非 ASCII 文件名的包 → 报 `Unsafe path in archive`，拒绝解压
- **根因**：bsdtar 在 `LANG` 为空的环境下，把非 ASCII 文件名输出成**八进制转义**
  （`./\344\270\255...txt`），而我们的安全检查把「反斜杠」判定为路径穿越
- **为什么隐蔽**：`LANG` 为空正是 **SSH / launchctl / 双击启动的 .app** 的常态
  —— 而 DLsite 的中文日文游戏文件名几乎必然含非 ASCII

→ 已在启动 tar 时显式提供 UTF-8 locale。**真机验证：故意清空 LANG，修复后 1587 条测试全绿。**

### 2. Siglus 的下载地址是 404

之前写的地址是猜的（资产名与 tag 两处都错）。现在改为实测可下载的地址，
并新增一条守卫：**任何新加的下载地址必须在实测清单里登记**，否则测试会红。

### 3. TyranoScript 的 v5 形态认不出来

原识别规则只覆盖 v4 未打包形态。v5 是 Electron，网页根在 `resources/app/` 里，深了一层。
已补。

### 4. 空依赖的引擎会显示「安装」按钮，点了必然失败

TyranoScript 复用 NW.js 运行时（`dependencies` 是空对象），但引擎页原来无条件显示「安装」。
现在改为显示「无需单独下载」。

### 5. 「全部安装」的数字会撒谎

空依赖引擎会被算进「待安装数量」，导致「说装了 3 个、实际只装 2 个」。已修。
