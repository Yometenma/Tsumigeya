# 打包与分发（GitHub Actions）

## 怎么拿到安装包

推送代码到 GitHub 后，Actions 会自动跑三件事：

1. **检查**（ubuntu）：`typecheck` + `test` + `build`
2. **打包 macOS**（macos-14）：分别产出 **arm64** 和 **x64** 的 dmg
3. **打包 Windows**（windows-latest）：产出 NSIS 安装包（调试 UI 用）

产物在 Actions 页面 → 对应的 run → 底部 **Artifacts** 下载，保留 14 天。

### 发布正式版本

打 tag 会自动创建 **draft Release** 并把所有产物挂上去：

```bash
git tag v0.1.0
git push origin v0.1.0
```

然后到 GitHub Releases 页面确认并 Publish。

## 首次使用需要做的

```bash
# 仓库还没关联远程的话
git remote add origin git@github.com:<你的账号>/Tsumigeya.git
git push -u origin main
```

推送后 Actions 自动开始。也可以到 Actions 页面点 **Run workflow** 手动触发。

**不需要配置任何 Secrets** 就能出可用的包（见下方签名说明）。

## 关于签名（重要，别被"已损坏"吓到）

当前配置**没有代码签名**：

- `electron-builder.yml` 里 `mac.identity: null` → 走 **ad-hoc 签名**
- CI 里 `CSC_IDENTITY_AUTO_DISCOVERY: false` → 不去找开发者证书

**后果**：macOS 上首次打开会提示「无法验证开发者」，需要：

- 右键点 App → **打开** → 再点「打开」，或
- 终端执行：`xattr -dr com.apple.quarantine /Applications/Tsumigeya.app`

这不影响功能，只是 Gatekeeper 的门槛。自己用完全够。

### 什么时候需要真签名

要发布给陌生人用、不想让他们看到警告，就需要 Apple 开发者账号（$99/年）+ 公证（notarize）。届时：

1. 在仓库 Settings → Secrets 添加：
   - `CSC_LINK`（.p12 的 base64）
   - `CSC_KEY_PASSWORD`
   - `APPLE_ID` / `APPLE_APP_SPECIFIC_PASSWORD` / `APPLE_TEAM_ID`
2. 把 `electron-builder.yml` 的 `mac.identity` 改成真实证书名（或删掉该行让它自动发现）
3. CI 里去掉 `CSC_IDENTITY_AUTO_DISCOVERY: false`，加 `notarize: true`

## 已知限制（记录，免得下次踩）

| 限制 | 说明 |
|---|---|
| **dmg 只能在 macOS 上构建** | electron-builder 不支持从 Windows/Linux 交叉编译 dmg，所以必须用 macos runner |
| Windows 上**无法本地验证**打包 | 本机（受限沙箱）在 electron-builder 解压 Electron 时会卡在 `default_app.asar` 的 `EPERM/EBUSY`，与配置无关。配置正确性以 CI 为准 |
| 架构分开打 | `mac.target` 不写 arch，由 CI 的 `--arm64` / `--x64` 指定，避免重复构建 |
| core 不进 asar | `extraResources` 把 `resources/core` 放到 `Contents/Resources/core`；`resolveCorePath` 的 `isPackaged` 分支读这个路径，两者必须一致 |
| Artifacts 保留 14 天 | 要长期保存就发 Release（tag 触发） |

## 排查 CI 失败

| 现象 | 原因 |
|---|---|
| `npm ci` 报 lockfile 不一致 | 本地执行 `npm install` 后把 `package-lock.json` 一起提交 |
| mac 打包报 `Cannot find module 'out/main/index.js'` | `electron-builder` 前忘了 `electron-vite build`；CI 里已由 `npx electron-builder` 前的步骤保证（本仓库用了 `npm ci` + 直接 builder，**注意**：builder 不会自动 build，需确认 CI 里先跑了 `npm run build`） |
| dmg 里缺 `core/module.js` | `extraResources` 配置或 `.gitignore` 误伤了 `resources/core` |
