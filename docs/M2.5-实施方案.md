## 1. 已实测确认的技术前提（**不要重复验证**）

### 1.1 DLsite 搜索**可用**，格式如下

```bash
# 唯一有效的搜索 URL（其余格式要么 404，要么返回"条件搜索页"而非结果）
https://www.dlsite.com/maniax/fsr/=/keyword/<URL编码关键词>

# 必须带 Cookie: adultchecked=1（否则 R18 区拿不到）
```

实测结果（2026-11-04）：

| 关键词 | `<title>` | 提取到的 RJ 数 |
|---|---|---|
| `傭兵` | `傭兵 日本語作品 言語不問作品 検索結果 \| DLsite 同人 - R18` | **25** |
| `傭兵の冒険`（错打成冒陪） | 同样回显关键词 | 0 |

**关键判据**：`<title>` 里含 `検索結果` 说明是真搜索结果页；不含则说明进了别的页面。

### 1.2 搜索结果解析：**能拿到 RJ + 标题**

页面里每个作品是这种结构（实测抓到 62 条/页，去重后 22–25 个作品）：

```regex
product_id/(RJ[0-9]{6,8})\.html"[^>]*>\s*([^<]{3,80})
```

**必须过滤的噪音文案**（都在同一页的按钮上，会污染标题）：

```
カートに追加
お気に入りに追加
詳細
```

按 RJ 去重，保留第一个非噪音标题。

### 1.3 **搜索精度一般，必须让用户自己挑**

实测：搜 `傭兵` 首条是「即ハメ王女」，**不是**目标游戏。
所以 UI 必须做成**候选列表让用户点选**，不能自动选中第一条。这正是用户要的。

### 1.4 不存在的 RJ 返回 **200**，不是 404

```
RJ99999999 → HTTP 200，title 为「エラー: この作品は現在販売されていません」
             var contents 存在但 detail 为空
```

**所以判断"作品不存在"必须看 `contents.detail[0]` 是否存在，不能靠状态码。**
（M2 现实现已按此处理，新增搜索功能时沿用。）

### 1.5 `lang_options` **不是**多语言版本的依据

```json
"lang_options": "JPN"      ← 这个作品自身支持的语言
```

它是**作品单值字段**，不是"同一游戏的多语言版列表"。
DLsite 上不同语言版通常是**独立的 RJ 号**（不同商品页）。
所以 §C 的"语言偏好"**与 DLsite 无关**，是本地文件层面的事。

## 3. §B：可编辑元数据

### B.1 数据契约扩展

`library-meta.json` 的条目**新增两个可选字段**（只增不改，向后兼容）：

```jsonc
{
  "1": {
    "rj": "RJ294126",
    "title": "…",            // （原有字段不变）
    // ↓ 新增
    "edited": true,                          // 该条目被手动编辑过
    "editedFields": ["title", "circle"]      // 哪些字段是用户改的
  }
}
```

### B.2 覆盖规则（**关键，别搞错**）

| 场景 | 行为 |
|---|---|
| 用户手动改了 `title` | `editedFields` 含 `title`；后续 `refreshGameMeta` **不覆盖**该字段 |
| 用户想恢复原始值 | UI 提供「重置此字段」→ 从 `editedFields` 移除 → 下次刷新会取回 DLsite 值 |
| 用户勾选「强制覆盖全部」 | 清空 `editedFields` 后整体刷新 |

实现位置：`src/main/library-meta.ts` 的合并函数 + `ipc.ts` 的 `refreshGameMeta`。

### B.3 可编辑字段（第一版只做这 5 个）

`title` / `circle` / `coverUrl` / `registDate` / `price`

**不给编辑** `rj`（改 RJ 等于换作品，应该走"重新搜索/填 RJ"流程）。

### B.4 UI

编辑页元数据区每个字段旁加铅笔图标 → 弹小输入框 → 保存后调 `saveGameMeta`（带 `editedFields`）。

### B.5 测试（`test/library-meta.test.ts` 追加）

- 保存带 `editedFields` 的条目 → 读回一致
- `refreshGameMeta` 时被编辑的字段**不被覆盖**，其余字段被更新
- 重置某字段后，下次刷新能取回 DLsite 值
- 旧格式条目（无 `edited`/`editedFields`）读回不报错（向后兼容）

## 4. §C：多语言版本偏好

### C.1 先厘清：这与 DLsite 无关

用户最初以为是"DLsite 上同一游戏的多语言版"。实测证明 `lang_options` 是**作品单值**，
不同语言版是独立 RJ。**所以这个功能是本地文件层面的事**：

> 同一个游戏，用户机器上有多个语言版本文件夹，希望启动时按偏好选。

### C.2 用户拍板的判定方式：**标题相似度 + 路径语言后缀**

保守规则（宁可少认，不要错认）：

```
1) 路径（目录名或文件名）里含语言标记：
   CHN/CN/CHS/SC/简中/中文  → zh
   JPN/JP/JA/日文           → ja
   ENG/EN/US/英文           → en
   KOR/KR/韩文              → ko
2) 两个游戏被归为「同一游戏的多语言版」需同时满足：
   a. 两者都识别出语言标记，且不同
   b. 标题归一化后相似度 ≥ 阈值（归一化：小写、去空白、去括号内容、去 _CHN 之类后缀）
3) 绝不把「没有语言标记」的游戏拉进任何组
```

**阈值建议 0.8（归一化后 Levenshtein 或简单字符集相似）**，实施时先拿用户的真实样本调。
用户样本（`E:\Game\RPG`）：

```
傭兵の冒険/傭兵の冒険_CHN          → ja 标题「傭兵の冒険」 zh
傭兵の冒険（仅此一个时不成组）
```

### C.3 语言后缀剥离（同时供 §A.3 的关键词默认值复用）

```ts
export function stripLanguageSuffix(name: string): { base: string; lang?: 'zh'|'ja'|'en'|'ko' }
```

例：`傭兵の冒険_CHN` → `{ base: '傭兵の冒険', lang: 'zh' }`
    `Game_v1.0.10` → `{ base: 'Game', lang: undefined }`（版本号也要剥，但它不是语言）

### C.4 设置项

```ts
interface Settings 新增:
  preferredLanguage: 'zh' | 'ja' | 'en' | 'ko' | 'none'   // 默认 'zh'？
  fallbackLanguage:  'zh' | 'ja' | 'en' | 'ko' | 'none'   // 默认 'ja'？
```

**默认值要用户再确认一次**（本文件暂定 `preferred=zh`、`fallback=ja`，因为用户是中文用户且玩日系游戏）。

### C.5 行为

- 游戏库卡片/列表对「组内非首选」的条目标记「也有 {lang} 版」
- 点启动时，如果当前条目不是偏好语言版，弹确认：「你更偏好 {lang} 版，要启动那个吗？」（可设为不再询问）
- **不自动删除/隐藏**其他语言版（那是用户数据，绝不代删）

### C.6 测试

- `stripLanguageSuffix` 各种输入（`_CHN` / `_v1.0.10` / 混合 / 无后缀 / 中文目录名）
- 分组：同标题 + 不同语言 → 成组；同标题 + 同语言 → 不成组；无语言标记 → 不成组
- 相似度阈值边界

## 6. 硬约束（重复一遍，都是踩过坑的）

1. **模板里禁止 TS 类型断言** —— 会让整块组件白屏（AGENTS.md 已知坑）

5. **contextBridge 跨边界抛错会丢 `error.key`** —— 已有 `src/shared/bridge-error.ts` 处理，别绕过
6. **`.vue` 里 `watch({ immediate: true })` 调用的函数不能引用后面声明的 ref** —— TDZ 会白屏
7. **所有 UI 文案进 `locales/zh-CN.json`**
8. **不改 `GameRecord` schema（D10）** —— 元数据一律旁挂
