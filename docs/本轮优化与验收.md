# 核心流程优化与验收

本轮按实际操作路径整治可靠性和状态反馈，保持现有 SwiftUI / Core / CLI 三 target 架构。

## 已修复

- 游戏库读取失败单独展示错误、原件位置和重试入口；添加时拒绝覆盖损坏原件。
- 搜索或分类筛选无结果时显示说明与清除入口；分类栏支持横向滚动。
- 游戏切换时在 GamePane 外层设置 identity，避免上一个游戏的编辑状态延续。
- 添加向导重新选择无法识别的文件时清空旧引擎，避免误用上一次检测结果。
- 编辑页将作品信息放入草稿，纳入保存、还原和变更判断；引擎参数 schema 跟随暂存引擎，各引擎分别保留草稿。
- 移除时清理元数据、归属、游玩记录与内存缓存；运行中拒绝移除；旧网络请求不得回写已移除/编号复用的游戏。
- 停止进程移到后台等待，界面显示“正在停止”。
- 安装失败在对应引擎行显示原因；残留目录不再阻挡安装；取消后等待原任务结束才释放任务槽，旧进度事件不能污染后续任务。
- 引擎操作移至独立 AppStore+Engines 扩展，避免继续堆进 AppStore 主文件。
- 设置、分类和元数据写盘失败不再发布成功状态。
- library-meta 写操作拒绝损坏原件，保留嵌套未知字段，分类保存读取最新元数据；进程内共享文件读改写加锁。
- JSON 写入改为原子替换，取消先删正式文件的窗口；备份失败时停止写入。
- 存档导入拒绝路径穿越、重复文件名和保留名称；所有校验通过、所有备份成功后才开始写入，备份失败不再继续覆盖原存档。
- UI 快照直接复用生产 RootView，并新增搜索无结果快照。

## 回归验证

在 macOS 26.6.2 / Apple Silicon / Swift 6.4.2 通过 SSH 执行 `swift build`、`swift test` 和 `Tsumigeya --snapshot`。新增测试直接调用 AppStore，覆盖损坏文件保护、编号复用、失败不发布状态、安装重试与取消；Core 测试覆盖未知字段及真实 zip 存档安全路径。

最终结果：`swift build` 成功；`swift test` 的 459 项测试（94 个套件）全部通过；7 张快照全部通过空白检查。新增纯色、单点噪声与中央稀疏内容对照，快照采样由 12×12 改为覆盖全图的 64×64，避免漏过空状态的中央文字。

UI 快照可检查视图渲染和空白输出；当前会话模型不支持图片输入，不能据此宣称完成目视观感验收。AsyncImage 离屏封面的限制仍适用。

## 后续建议

- 为编辑草稿补齐 SwiftUI 交互自动化，验证输入、返回、还原及失败重试；目前主要通过状态测试和静态审查验证。
- 将跨多个 JSON 文件的删除与编辑提交演进为可恢复事务。当前单文件写入原子，但跨文件并非全有或全无；编辑第二步失败会明确提示已保存的本地信息，并保留作品信息草稿。
- 逐步把源码字符串扫描测试替换为直接行为测试；本轮已让测试 target 引入 App 模块。
- 下载、安装和启动仍应继续用真实游戏与实际网络验收，现有测试不能证明所有引擎兼容性。
