## 2. 目标与范围

**一句话**：拖进一个游戏文件夹 → 自动识别引擎 → 没装就一键装 → 点启动调原生播放器。

- 做：游戏库（增删改查/图标/标签/搜索/列表-网格）、添加向导（路径 → 识别 → 装引擎 → 保存）、
  游戏编辑（标题/路径/引擎/标签 + 引擎参数表单 + 多版本管理）、引擎管理（已装/远程/安装/更新/卸载/批量更新）、
  设置（外观/列表视图/删除确认/启动检查更新/数据目录）、进度浮层 + 取消、core 对话框桥。
- **不做**（M2+）：DLsite 元数据、存档管理、RTP/字体自愈、Cheat/变速、手柄、dmg 公证。
- 真实验证边界：Windows 上只能验证到「识别 + 装引擎 + 调起 launcher.js」，**真实启动游戏必须 macOS**。

### 2.1 复用边界与许可影响

**结论：不是把 Xenolauncher 整个搬进来，只复用了 1 个纯逻辑文件。**

| 上游文件 | 行数 | 本项目是否包含 |
|---|---:|---|
| `app/module.js` | 1870 | ✅ **唯一复用**（`resources/core/module.js`，72KB，差异见 `FORK-NOTES.md`） |
| `app/*.html`（index / game-settings / status / module-manager / version-manager） | 2688 | ❌ 用 Vue3 页面重写 |
| `app/main.css` | 844 | ❌ 自己的样式（Element Plus + 暗色主题） |
| `app/games.js` / `global-settings.js` / `window-utils.js` | 407 | ❌ 主进程 `games-store` + IPC 重写 |
| `native/Backend/worker.cjs` | 410 | ❌ 只作 IPC 范本参考，不打包 |
| `native/Translations/*.json` | 414 | ❌ 自己的 `locales/zh-CN.json` |

- `_xeno_probe/` 是 gitignore 的只读参考，不进构建产物。
- 安装包内容 = `out/**`（我们的编译产物）+ `resources/core` → `core/module.js`（`electron-builder.yml` 的 `extraResources`）。
- `module.js` 能脱壳复用的原因：UMD 工厂，Node 分支只做 `module.exports = factory`，运行时仅依赖注入的 5 个服务
  （`getAppSupportDir / getGames / getUi / extractArchive / fetch`），不 `require` 任何上游 UI；
  注入 `extractArchive` 后，上游的可选解压依赖 `unzipper / tar / lzma-native` **完全不会被 require**（`module.js:976` 早退），
  因此本项目**不需要**装这三个包。
- 复用的是**代码**；另外沿用三项**约定**（不是代码复制）：manifest.json 格式、模块仓库 `m5kro/Xenolauncher-Modules`、
  数据目录位置（D3 / D10）。沿用约定是为了直接吃上游引擎模块生态 + 老用户游戏库零迁移。
- **许可**：分发物包含 GPL-3.0 代码 → 整个 Tsumigeya 是衍生作品，发布必须开源（D2 已接受）。
  若不能接受该约束，唯一干净路径是不复用该文件、从零重写模块系统（manifest 格式可沿用，格式本身不受版权保护），
  成本约 2000 行 + 行为细节重踩，收益只是去掉 GPL 传染。

### 3.3 IPC 命令表（`tsumi:invoke`）

入参统一 `{ method, params, requestId }`，返回 `{ ok:true, result }` 或 `{ ok:false, error:{ message, key?, arguments? } }`。
**除特别标注外全部进串行队列**（`queue = queue.then(...)`），队列内用各请求自己的 `AbortController`。

| # | method | 入参 | 返回 | 主要失败键 |
|---|---|---|---|---|
| 1 | `snapshot` | — | `Snapshot` | — |
| 2 | `saveGame` | `{ id?: string, game: GameDraft }` | `Snapshot` | `error.missingGame` / `error.requiredGame` / `error.duplicateGame` / `error.staleGame` / `error.invalidComponent` |
| 3 | `saveSettings` | `Partial<Settings>` | `Snapshot` | `error.appearance` / `error.language` |
| 4 | `deleteGame` | `{ id: string }` | `Snapshot` | `error.gameNotFound` / `error.cleanup` |
| 5 | `launch` | `{ id: string }` | `{ message: string }` | `error.gameNotFound` / `error.gamePath` / `error.moduleMissing` / `error.launchExport` / `error.launchFailed` |
| 6 | `detect` | `{ path: string, includeRemote?: boolean }` | `{ engine: string \| null, installed: boolean }` | — |
| 7 | `detectFolder` | `{ path: string, includeRemote?: boolean }` | `DetectFolderResult` | `error.pathMissing` |
| 8 | `remoteModules` | — | `RemoteModule[]` | `error.network` |
| 9 | `checkEngineUpdates` | `{ forceRefresh?: boolean }` | `EngineUpdateReport` | `error.updateCheckTimeout` |
| 10 | `updateAllEngines` | — | `Snapshot` | `error.checkUpdatesFirst` / `error.engineUpdateFailed` |
| 11 | `moduleTask` | `{ folder, action: 'install'\|'update'\|'dependencies'\|'uninstall' }` | `Snapshot` | `error.moduleAction` / `error.invalidComponent` |
| 12 | `installedVersions` | `{ folder, argKey }` | `string[]` | — |
| 13 | `versions` | `{ folder, argKey }` | `{ installed: string[], available: Record<string, unknown> }` | `error.notMultiVersion` / `error.moduleMissing` |
| 14 | `installVersion` | `{ folder, argKey, version }` | `{ installed: string[], available }` | `error.buildMissing` / `error.alreadyInstalled` / `error.download` |
| 15 | `removeVersion` | `{ folder, argKey, version }` | `{ installed: string[] }` | `error.notMultiVersion` |
| 16 | `pickPath` | `{ kind: 'file' \| 'folder' }` | `string \| null` | —（**不进队列**，独立 `ipcMain.handle('tsumi:pick')`） |
| 17 | `openFolder` | `{ path: string }` | `{ ok: true }` | `error.pathNotAllowed`（只允许数据目录或某个已登记游戏的目录） |
| 18 | `openExternal` | `{ url: string }` | `{ ok: true }` | `error.unsupportedProtocol`（只允许 `https:`） |

**不在表里的命令一律返回 `error.unknownMethod`**（照 `worker.cjs:370`）。

`detectFolder` 的扫描规则（新能力，上游只有单文件 `detect`）：

1. `path` 是文件 → `candidates = [该文件]`。
2. `path` 是目录 → 扫**顶层 + 一层子目录**里扩展名属于
   `exe, app, msi, bat, sh, command` 的文件，最多 200 个；跳过 `node_modules`、以 `.` 开头的目录。
3. 排序：文件名含 `game`（不分大小写）优先 → 扩展名权重 `app > exe > command > sh > bat > msi` → 浅层优先 → 路径字典序。
4. 每个候选跑 `core.detectEngineForPath(候选, core.readLocalManifests())` → `installed: true`。
5. `best` 取第一个 `installed === true` 且 `engine` 非空的候选；没有时取第一个 `engine` 非空的。
6. 若 `best === null` 且 `includeRemote !== false` → `core.fetchModulesForAutodetect()` 拿到未装模块的规则，再对候选跑
   `core.detectEngineFromAutodetectMap()`，此时命中的候选 `installed: false`。
7. 返回值里 `candidates` 保留全部结果（UI 可让用户改选），`best` 只是推荐。

### 3.4 事件协议（主进程 → 渲染进程，频道 `tsumi:event`）

照 `worker.cjs` 的 `event()` / `progress()`：

```ts
// 进度：name ∈ onStepTotal|onStep|onDownloadStart|onProgress|onDownloadProgress|onDownloadEnd
{ event:'progress', requestID?, name?, key?, detail?, arguments? }
// 日志（core 内 console.*）
{ event:'log', requestID?, message: string }
// 对话框（core 的 ui.alert / ui.confirm）
{ event:'dialog', requestID?, dialogID, kind:'alert'|'confirm', title, message }
// 就绪
{ event:'ready', nodeVersion: string }
```

- `key` 形如 `progress.download` / `progress.extracting` / `updates.checking` / `updates.updatingEngine`，
  渲染层优先用 `key` 查 `locales` 文案，没有 `key` 时退回 `name`。
- 对话框应答走 `tsumi:dialog { dialogID, accepted }`，**必须绕开队列**，否则死锁（core 在队列里等 answered）。
- 取消走 `tsumi:cancel { requestId }`，也是直连，不进队列。

### 3.5 preload API（`window.tsumi`，contextBridge）

```ts
export interface TsumiBridge {
  invoke<T>(method: string, params?: unknown): Promise<T>          // 失败时 throw Error，附 .key / .arguments
  startTask<T>(method: string, params?: unknown): { requestId: string; promise: Promise<T> }  // 可取消的长任务
  cancel(requestId: string): void
  dialogReply(dialogId: string, accepted: boolean): void
  pickPath(kind: 'file' | 'folder'): Promise<string | null>

  readonly appVersion: string

```

`startTask` 与 `invoke` 唯一差别是它把生成的 `requestId` 一起返回，供「取消」按钮使用；

### 3.6 core 装载方式（重要，别用裸 require）

`module.js` 是 UMD，Node 分支执行 `module.exports = factory`。**不要** `require(corePath)`：
Vite/rollup 会改写/外置它，打包后路径与形态都会变。用读取源码 + 手工执行：

```ts
import { createRequire } from 'node:module'
import { pathToFileURL } from 'node:url'

function loadCoreFactory(corePath: string) {
  const source = fs.readFileSync(corePath, 'utf8')
  const mod: { exports: unknown } = { exports: {} }
  const nodeRequire = createRequire(pathToFileURL(corePath))
  const run = new Function('module', 'exports', 'require', '__filename', '__dirname', source)
  run(mod, mod.exports, nodeRequire, corePath, path.dirname(corePath))
  return mod.exports as (services: CoreServices) => CoreApi
}
```

`CoreServices` 只注入这 5 个：

```ts
{ getAppSupportDir: () => string, getGames: () => { loadGames, saveGames }, getUi: () => DialogBridge,
  extractArchive: (archive, dest, { signal }) => Promise<void>,
  fetch: (input, init) => net.fetch(input as any, init) }   // D9：走系统代理
}
```

core 实例**全进程一个**（`core-host.ts` 里 `let core` 缓存），并在 `app.whenReady()` 之后创建。

### 3.7 `tsmg://` 协议（图片）

- `app.whenReady()` 之前：`protocol.registerSchemesAsPrivileged([{ scheme:'tsmg', privileges:{ standard:true, secure:true, supportFetchAPI:true } }])`
- 之后：`protocol.handle('tsmg', ...)`
- URL 形式：`tsmg://img/<encodeURIComponent(绝对路径)>`
  解析：`const p = decodeURIComponent(new URL(request.url).pathname.slice(1))`
- 校验顺序：绝对路径 → 扩展名白名单 `png jpg jpeg webp gif bmp avif ico` → 存在且是文件 → `net.fetch(pathToFileURL(p))`
- 不合法一律 `new Response(null, { status: 404 })`，不要抛到主进程。
- 渲染层封装 `iconUrl(p?: string): string | undefined`。

### 3.8 `launch` 自实现（D5）

```
1. games.load()[id]                 → 无 → error.gameNotFound
2. fs.existsSync(gamePath)          → 否 → error.gamePath
3. core.reconcileAndPersistGameArgs(String(id))    // 按 manifest.gameArgs 合并缺省值并落盘
4. loadScript(engine, 'launcher.js')               // 路径逃逸校验 + 清 require 缓存
5. typeof launcher.launch !== 'function'           → error.launchExport
6. darwin 才补 chown/xattr/chmod（execFile，失败只记日志，不等）
7. await launcher.launch(gamePath, folder, gameArgs, gameTitle, ui)   // folder = 文件则取 dirname
8. 返回 { message: '已发送启动请求' }
```

`loadScript` 安全校验（照 `worker.cjs:62-67`）：`path.resolve` → `realpathSync` → 必须落在模块根目录内，否则 `error.scriptEscape`；
模块目录若是符号链接直接拒绝（`error.linkedModule`）。

## 10. 变更记录（契约冻结后的调整）

> 规矩：本节只记**已实施**的契约调整，每条写明理由。没有条目就代表实现与 §3–§4 完全一致。

### C1（2026-11-04）`/library/new` 指向 `AddGameWizard` 而不是 `GameEditPage`

- **原契约**：§4 把 `/library/new` 列在 router 里，`GameEditPage` 职责写作"编辑/新建"。
- **实际**：`/library/new` → `AddGameWizard.vue`；`/game/:id` → `GameEditPage.vue`。
  `GameEditPage` 内部保留 `isNew` 分支（直接访问 `/library/new` 的旧链接仍然安全）。
- **理由**：新建游戏的正确形态是三步向导（选路径 → 识别/装引擎 → 完善信息），
  直接落到编辑页会跳过"识别引擎 + 一键装引擎"这条核心链路；而 `GameEditPage` 是纯编辑表单，
  嵌不下"识别 → 安装"的中间状态。
- **影响面**：只涉及路由映射，**文件清单、IPC 表、数据结构、事件协议均未改动**。

### C2（2026-11-04）`TsumiBridge` 增加 `pathForFile(file)`

- **原契约**：§3.5 的桥只有 invoke / startTask / cancel / dialogReply / pickPath / onEvent / platform / appVersion。
- **实际**：新增 `pathForFile(file: File): string | null`（内部走 `webUtils.getPathForFile`）。
- **理由**：Electron 32+ 已移除 `File.path`，在 Electron 45 上拖拽得到的 `File` 对象**没有路径信息**，
  向导的"拖拽添加游戏"会静默失效。这是唯一能拿到拖入路径的官方途径。
- **影响面**：只加了一个桥方法，**没有新增 IPC 命令**（纯 preload 侧同步调用），
  IPC 18 条命令表、事件协议、数据结构都不变。
