## 1. 目标与范围

### 1.1 一句话目标

**给已有游戏记录挂上 DLsite 元数据（RJ 号 → 标题 / 社团 / 封面 / 发售日 / 价格 / 分类），
做成"能看见封面的游戏库"，且上游 `GameRecord` schema 零改动。**

### 1.2 做（M2-A）

| # | 功能 | 说明 |
|---|---|---|
| A1 | **RJ 号识别** | 从游戏路径 / 目录名 / 目录内 `readme*.txt` 里提取 `RJ\d{6,8}`；用户可手填覆盖 |
| A2 | **元数据拉取** | 走 `host.fetch`（即 `net.fetch` + `setProxy({mode:'system'})`），解析页面末尾 `var contents` JSON |
| A3 | **旁挂存储** | `<dataDir>/library-meta.json`（按 gameId）+ `<dataDir>/dlsite/<RJ>.json`（按 RJ 缓存，带 TTL） |
| A4 | **UI：封面墙 + 详情卡** | 网格模式以封面为主视觉；编辑页展示元数据并可手动刷新 |
| A5 | **失败可见** | 网络不通 / 页面结构变化 / RJ 不存在，都给中文可操作提示，**不静默失败** |

### 1.3 **不做**（写进契约，防止下一个会话翻案）

| # | 不做 | 理由 |
|---|---|---|
| N1 | **标签 / genre** | 调研 §3 实测：`product/info/ajax` 返回 `[]`，`api/product` 404，JSON-LD 无 Product。**多请求方案不可行**，不承诺 |
| N2 | 不给 `GameRecord` 加字段 | D10，见 §3.1 |
| N3 | 不做批量全库抓取 | 会打爆代理与 DLsite 限速；只做"当前这一个游戏"的单次查询 |
| N4 | 不做封面本地缓存（v1） | 见 §7.4，留作**实测失败后**的备选，不在本期承诺 |
| N5 | 不解析 HTML 详情表 | 调研 §4.1 结论：只用 `var contents` JSON |
| N6 | 不自建 DLsite 代理服务 / 不内置第三方 API | 调研 §3 已判死 |

| 约束 | 本方案怎么守 |

## 3. 数据契约

### 3.1 为什么这样切（复核 D10 边界）

`games.json` 的磁盘形态是 `{ "<id>": 不含 id 的记录 }`，`saveGame` 用**浅合并保留未知字段**（`games-store.ts:181-187`）。
理论上塞字段进去"不会坏"，但那会让上游读到的记录里出现它不认识的东西，且一旦我们以后改字段语义就变成**语义污染**。
所以：

- **上游 schema 零改动** = 验收硬标准；
- 我们的数据住自己家里，删掉 `<dataDir>/library-meta.json` 游戏库照常能启动。

### 3.2 新增文件 `<dataDir>/library-meta.json`

按 **gameId** 键控（不是 RJ，因为一个游戏可能暂时没 RJ）：

```jsonc
{
  "1": {
    "rj": "RJ294126",
    "title": "純愛おま○こ当番【アップデート版】",
    "circle": "青春×フェティシズム",
    "circleId": "RG51931",
    "coverUrl": "https://img.dlsite.jp/modpub/images2/work/doujin/RJ295000/RJ294126_img_main.jpg",
    "registDate": "2020/08/30",
    "category": "maniax",
    "workType": "SOU",
    "price": 750,
    "priceWithTax": 1650,
    "fetchedAt": "2026-11-04T00:00:00.000Z"
  }
}
```

- 写入一律走 `games-store.ts` 的 `writeJSON`（已有原子写 + `.bak` + 损坏文件不静默覆盖）。
- **冗余存关键字段**（title/circle/coverUrl…）而不是只存 `rj`：这样 `<dataDir>/dlsite/` 缓存过期或被清掉，
  封面与社团名仍然能显示，不变成"点了刷新才回来"。
- 删除游戏时**同步删除该 gameId 的条目**（保持一致性）；**不**删 `dlsite/<RJ>.json`（RJ 缓存可跨游戏共享）。

### 3.3 新增缓存文件 `<dataDir>/dlsite/<RJ>.json`

```jsonc
{ "rj": "RJ294126", "work": { ...DlsiteWork... }, "fetchedAt": "2026-11-04T00:00:00.000Z" }
```

- RJ 必须过 `component()` 级别的校验（`/^RJ\d{6,8}$/`），**绝不**允许把外部输入直接拼进路径。
- TTL **7 天**；`refresh: true` 强制重取。

### 3.4 `DlsiteWork` 类型（主进程 + 渲染层各一份，风格照现有"三处同步"）

```ts
export interface DlsiteWork {
  rj: string                // 规范化大写，如 RJ294126
  title: string             // contents.detail[0].name（页面 h1 同名）
  titleFull?: string        // og:title 去掉尾部 " | DLsite"
  circle?: string           // 从 og:title 的 "[社团名]" 提取（见 §4.4），失败再试面包屑
  circleId?: string         // contents.detail[0].brand（= RG号）
  seriesName?: string       // contents.detail[0].series_name
  category: string          // contents.detail[0].category
  workType?: string         // "SOU" 等；UI 只显示"作品类型"标签，不当 genre 用
  registDate?: string       // "2020/08/30"
  price?: number            // discount 后
  priceWithTax?: number
  officialPrice?: number
  discount?: number
  coverUrl?: string         // 已归一化成 https: 绝对地址
  description?: string      // og:description，截断 400 字（避免塞爆 library-meta.json）
  fetchedAt: string
}
```

### 3.5 `Snapshot` 变更（唯一改动的既有契约）

```diff
 export interface Snapshot {
   games: GameRecord[]
+  /** 旁挂元数据（M2）。键 = gameId；无元数据的游戏不会出现在这里。 */
+  meta: Record<string, GameMeta>
   ...
 }
```

`snapshot()` 里读 `library-meta.json`（小文件、一次读，`snapshot` 本来就是绕队列的）。
渲染层 `library.ts` 的 `applySnapshot` 同时写入 `meta` ref（**一处改动，全 UI 自动同步**）。

## 4. 网络层设计（`src/main/dlsite.ts`，纯逻辑，不 import electron）

### 4.1 请求

```
GET https://www.dlsite.com/maniax/work/=/product_id/{RJ}.html
Headers: User-Agent: <Electron/Chrome UA>；Accept: text/html
Cookie: adultchecked=1  （R18 年龄闸门，不设就只能拿到确认页）
```

- **代理**：不改任何东西。`host.fetch` 已经是 `index.ts:150` 注入的 `net.fetch`，
  且 `whenReady` 里 `await session.setProxy({ mode: 'system' })` 已生效（调研已确认）。
- **超时**：`AbortSignal.any([调用方 signal, AbortSignal.timeout(15_000)])`。超时 → `error.dlsiteTimeout`。
- **分类回退**：`maniax` 拿到 404/空 JSON 时，再试 `homepro`（全年龄作品常落在别的 section）。
  两次都失败才报 `error.dlsiteNotFound`。DLsite 通常 301 到正确 section，`net.fetch` 默认跟随重定向。
  **这条列为"实施时实测确认"项**（§11 R1）。
- **不做自动重试**（除上面那一次分类回退）；失败就报错让用户点"重试"，避免无声磨蹭。
- **同 RJ 并发合并**（in-flight Map）：连点两下只发一次请求。
- **节流**：全局最小请求间隔 800ms（M2 只有单条查询，成本极低，防未来批量误用）。

### 4.2 Cookie 写入

`Cookie` 头在 Chromium 网络栈里可能被剥离，所以**主选 session cookie**：

```ts
// index.ts 注入，纯 Node 测试里传空实现
setAdultCookie?: () => Promise<void>
// 实现：session.defaultSession.cookies.set({
//   url: 'https://www.dlsite.com', name: 'adultchecked', value: '1',
//   domain: '.dlsite.com', path: '/', secure: true, expirationDate: <now + 365d>
// })
```

只写一次（模块内 `cookieReady` 标记），失败只 `console.warn` 不阻塞——大不了拿到确认页再报 `error.dlsiteParse`。

### 4.3 `var contents` 的健壮提取（**不用贪婪正则**）

调研给的 `/var\s+contents\s*=\s*(\{[\s\S]*?\})\;\s*<\/script>/` 有真实隐患：
description 里的日文字符串可能含 `};` 字样、页面别处也可能有 `var contents`。

**实现改成"定位 + 括号配对扫描"**：

1. 在 HTML 里找 `var contents` 的所有出现位置（取**最后一个**，最适合"页面末尾"）；
2. 从其后第一个 `{` 开始做**字符串感知**的深度扫描（识别 `"` / `\"` 转义，只在字符串外计数 `{` `}`）；
3. 深度归零处截断 → `JSON.parse`；
4. 失败逐层回退：改用 `contents.detail[0]` 是否存在作最终判据，任何异常 → `error.dlsiteParse`（附"页面结构可能已改版"文案）。

`\uXXXX` 由 `JSON.parse` 自动还原，不用手写反转义。

### 4.4 社团名从 `og:title` 取（省一次 HTML 解析）

`og:title` 形如：`純愛おま○こ当番【アップデート版】 [青春×フェティシズム] | DLsite`

正则 `/\s*\[([^\]]+)\]\s*\|/` 直接得社团名，**比面包屑解析稳**（面包屑 DOM 结构最容易改版）。
取不到时才退回调研 §2.1 的 `maker_id/(RG\d+)` 面包屑正则。

### 4.5 封面 URL 归一化

`contents.detail[0].image_main` 是 `//img.dlsite.jp/...`（协议相对）。
统一转 `https:${value}`，并**校验 host 必须在 `img.dlsite.jp`**（拒绝任何别的主机，防注入/防盗链怪 CDN）。

### 4.6 RJ 号识别

- 来源优先级：目录名 → `gamePath` 任一路径段 → 目录内 `readme*.txt` / `README*.txt`（限读前 64KB、最多 8 个文件）；
- 正则：`/[Rr][Jj]\s*[-_]?\s*(\d{6,8})/g`，取**第一个**命中，规范化为 `RJ<数字>`；
- 文件名带全角或 `RJ123456` 混在长串里都要能出；**命中多个不同 RJ 时返回全部候选**，让 UI 让用户选（避免瞎猜）。

## 5. IPC 变更

### 5.1 新增命令（`src/main/ipc.ts` 的 `dispatch` switch）

| 命令 | 参数 | 返回 | 队列 | 越权/写盘 |
|---|---|---|---|---|
| `dlsiteDetectRJ` | `{ path }` | `{ candidates: string[] }` | **绕队列**（只读本地文件、用户点一下就等） | 只读 |
| `dlsiteLookup` | `{ rj, refresh? }` | `DlsiteWork` | **绕队列**（见 5.3） | 写 `dlsite/<RJ>.json` 缓存 |
| `saveGameMeta` | `{ gameId, rj, work? }` | `Snapshot` | 进队列（写 `library-meta.json`） | 写 |
| `refreshGameMeta` | `{ gameId, refresh? }` | `Snapshot` | 进队列 | 写 |

> `dlsiteLookup` 只返回 work 不回 Snapshot：调用方（编辑页）拿到后自己再调 `saveGameMeta` 落盘。
> 这样"查"和"存"分开，查失败不会污染库，也方便 UI 先预览再确认。

### 5.2 三处同步

- `src/main/ipc.ts`：实现 + 类型
- `src/renderer/src/api/client.ts`：`DlsiteWork` / `GameMeta` / `dispatcher` 类型 + `api.*` 方法
- `src/preload/index.ts`：**不改**（没有新 channel）

### 5.3 `TASK` 旁路改造（并修一个既有隐患）

现状：

```ts
const TASK = method === 'detect' || method === 'detectFolder' || method === 'snapshot' || method === 'versions'
```

改成一个导出常量，方便测试锁死（防以后有人手滑把网络命令塞回来）：

```ts
export const OFF_QUEUE_METHODS = new Set([
  'detect', 'detectFolder', 'snapshot', 'versions',
  'dlsiteDetectRJ', 'dlsiteLookup'
])
```

**为什么 `dlsiteLookup` 可以绕队列**：它只写 `dlsite/<RJ>.json`（自己的目录，原子写），
不碰 `games.json` / `library-meta.json` / `modules/`，与其他队列内写操作**无共享资源**；
而它要等网络（15s 超时），塞进队列会重演"识别引擎被更新检查堵死"的老坑（AGENTS.md 已知坑倒数第 5 条）。

### 5.4 错误键（一律中文、可操作）

| key | 文案（`{...}` 只用简单占位符） |
|---|---|
| `error.dlsiteInvalidRj` | `RJ 号格式不正确：{rj}（应为 RJ 加 6–8 位数字）` |
| `error.dlsiteNotFound` | `DLsite 上找不到作品 {rj}，请确认 RJ 号` |
| `error.dlsiteTimeout` | `访问 DLsite 超时，请确认系统代理已开启后重试` |
| `error.dlsiteNetwork` | `网络请求失败：{reason}。DLsite 需要系统代理` |
| `error.dlsiteParse` | `无法解析 {rj} 的页面数据（DLsite 可能已改版）` |
| `error.dlsiteGameRequired` | `请先保存游戏，再获取 DLsite 信息` |

## 6. UI 改动

### 6.1 `GameEditPage.vue`：新增「DLsite 信息」面板

```
[ RJ 号 ]  [自动识别]  [获取信息]  [刷新]
  ├─ 识别到 RJ294126（也可手填）
  └─ 结果区：封面缩略图 + 标题 / 社团 / 发售日 / 价格 / 分类 + `在 DLsite 打开`
```

- 自动填入：进页面时用 `game.gamePath` 调一次 `dlsiteDetectRJ`（本地毫秒级，不进队列）。
- 「获取信息」：`dlsiteLookup` → 成功后 `saveGameMeta`（一次点击两步，UI 只显示"正在获取…"）。
- 预览顺序（**实施时确认**）：先展示、用户点「保存」再落盘；`取消` 丢弃。
- 「在 DLsite 打开」走既有 `api.openExternal`（已限 https ✅）。
- **所有 `as` 断言放在 script 里的具名函数**；模板只写运行时代码。

### 6.2 `GameCard.vue`：封面优先

- `props` 仍是 `GameRecord`，**再加一个 `meta?: GameMeta` prop**（避免把 meta 塞回 GameRecord）。
- 图像优先级：`meta.coverUrl` → 既有 `game.iconPath` → 首字母占位。
- 网格（`variant === 'card'`）：封面占主体（16:10 裁切），标题单行省略，悬停显示启动/编辑/删除。
- 列表（`variant === 'row'`）：封面做 40x40 缩略图，元信息行加社团名。
- `@error` 一律退回下一档（`broken` ref 已有，扩成 `coverBroken` / `iconBroken` 两级）。
  **远程图失败是常态场景，绝不能让卡片白块或空白区。**

### 6.3 `LibraryPage.vue`

- 把 `library.meta[game.id]` 传进 `<GameCard :meta="...">`（两处：row / card）。
- 顶部加筛选开关「只看有元数据」（不新增 settings 键，纯本地 ref，刷新页面重置）。

### 6.4 `stores/library.ts`

- 新增 `meta = ref<Record<string, GameMeta>>({})`，`applySnapshot` 里一并赋值。
- `filtered` 的搜索词额外匹配 `meta[id].title` / `circle`（日文原名可搜，顺带让"搜日文"可用）。
- 新增 `saveGameMeta` / `refreshGameMeta` / `lookupRJ` / `detectRJ` 四个 thin wrapper。

### 6.5 `index.ts` 的 CSP（调研 §4.1 第 4 条）

两处分支都要改（dev 与 prod，漏一处就会出现"dev 能看见封面、打包后全灰"的经典坑）：

```diff
-"img-src 'self' data: tsmg:",
+"img-src 'self' data: tsmg: https://img.dlsite.jp",
```

**只加 img-src，不动 `connect-src` / `script-src` / `default-src`**：
渲染层不需要向 DLsite 发 XHR（抓取全在主进程），`<img>` 不受 connect-src 管。

## 12. 与既有决策的关系（新增决策编号建议）

| # | 新决策 | 理由 |
|---|---|---|
| **D18** | DLsite 元数据**旁挂** `library-meta.json` + `dlsite/<RJ>.json`，`GameRecord` 零改动 | 守 D10；删了不影响启动 |
| **D19** | 只解析 `var contents` JSON，**不解析 HTML 表格**；标签功能不做 | 调研实测结论，避免结构改版连锁崩 |
| **D20** | 元数据抓取**只在主进程**做（渲染层不发网络请求），CSP 仅加 `img-src https://img.dlsite.jp` | 最小攻击面；`<img>` 不受 connect-src 约束 |
| **D21** | `dlsiteLookup` / `dlsiteDetectRJ` 进 `OFF_QUEUE_METHODS` | 只写自己的缓存目录，与队列内写操作无共享资源；防重演"更新检查堵死队列" |
| **D22** | 封面 URL 必须 host ∈ `img.dlsite.jp`，否则丢弃 | 外部数据不可信，禁止任意远程图进渲染层 |
