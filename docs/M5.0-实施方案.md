## 2. B1：版本号永远显示 v0.0.0（真 bug，一行就能修）

### 2.1 根因（已查实）

`src/preload/index.ts:109`：

```ts
appVersion: process.env.npm_package_version ?? '0.0.0'
```

**`npm_package_version` 只有 `npm run` 起的进程里才存在。** 打包成 .app 后由 Finder 启动，
环境变量**不存在** → 恒回落 `'0.0.0'`。

`App.vue:31` 直接读它：`window.tsumi?.appVersion ? 'v' + ... : ''`。

### 2.2 修法

主进程用 `app.getVersion()`（Electron 会读 `package.json` 的 version，打包后也对），
经 `tsumi:invoke` 或 preload 暴露出去。**preload 里拿不到 `app`**（那是主进程 API），所以：

```ts
// 主进程 index.ts，ready 后
ipcMain.handle('tsumi:version', () => app.getVersion())
// preload
appVersion: await ipcRenderer.invoke('tsumi:version')  // 或走现有 setup 流程
```

**注意 preload 是同步暴露的**（`contextBridge.exposeInMainWorld` 在 window 创建时执行）。
所以更稳的做法是：**主进程在创建窗口前把版本塞进一个额外参数**（`webPreferences.additionalArguments`
或直接 `BrowserWindow` 的 `query`）。

最简单可靠：**用 `electron-vite` 的 `define` 在构建时注入**：

```ts
// electron.vite.config.ts
define: { __APP_VERSION__: JSON.stringify(pkg.version) }
```

然后 preload 里 `appVersion: __APP_VERSION__`。**零运行时开销、打包后必对。**

## 3. B2：VX Ace 报错（**需要向用户要数据才能定位**）

### 3.1 现有检测逻辑（已查实，逻辑本身是对的）

```ts
detectEncryptedArchive(dir):
  if (有 .rgss3a/.rgss2a/.rgssad) {
    if (hasExtractedData(dir)) return null   // 有 Data/ 下的脚本 → 不报
    否则报 fatal「加密发行，需解包」
  }

hasExtractedData(dir):
  读 dir/Data/，有 .rb/.rvdata2/.rvdata/.rxdata 文件 → true
```

### 3.2 为什么用户放了 Data 还是报

**三种可能，必须拿到他的实际目录结构才能定**：

| # | 可能原因 |
|---|---|
| **a** | 用户把 `Data/` 放到了**子目录**里（如 `游戏名/Data/`），而 `gamePath` 指向的是父目录 → `dir/Data` 不存在 |
| **b** | `Data/` 里的文件**不是** `SCRIPT_EXTENSIONS` 里的扩展名（比如只放了 `System.rvdata2`，而脚本叫别的名） |
| **c** | 用户的 `gamePath` 指向的是**某个 exe 文件**，`resolveGameFolder` 解析出的目录不对 |

### 3.3 处置：**向用户要三样东西**

1. 那个游戏的**完整目录树**（`ls -R` 或截图，要到 `Data/` 那两层）
2. 报错**原文**（现在的中文文案是哪一条）
3. `library-meta` 里那条游戏的 `gamePath` 是什么

**在拿到之前不猜、不盲改**——改错了会把「真加密的游戏」也放过去。

## 4. U1 + U2：批量管理 + 自定义分类

### 4.1 批量管理

**现状**：库页**完全没有多选**（只有搜索 + 标签筛 + `onlyWithMeta`）。

**方案**：

```
库页顶部：进入「批量模式」按钮
  ↓
卡片左上角出现复选框；顶部工具条变成：
  [已选 N 个]  [全选]  [删除]  [设为分类 ▾]  [取消]
```

**关键约束**：
- 批量删除**必须二次确认**，且弹窗里要列出被删的标题（≥3 个时只列前 3 + 「等 N 个」）
- 批量操作走 `OFF_QUEUE_METHODS`？**不行** —— 写盘要进队列。但它可能很慢（N 个游戏），
  所以**要逐个执行 + 进度反馈**，不能一个失败全崩

### 4.2 自定义分类（用户拍板：**多归属**、**扁平**）

**用户原话**：「游戏需要能玩家自己分类，也可以配合上面多选的批量分类或归于某一类之类的」

**用户拍板**：**一个游戏可以同时属于多个分类**（像标签），**不做父子层级**。

**与现有 `tags` 的区别（重要，别混）**：

| 项 | `tags`（已有，上游 schema） | `categories`（新增，旁挂） |
|---|---|---|
| 语义 | 通用标记，用户手填 | **用户的整理体系**（侧边栏导航） |
| 存储 | `GameRecord.tags`（D10 不能动） | `library-meta.json` 新字段 |
| 谁创建 | 随手写 | **用户在侧边栏显式管理**（建/改名/删） |
| 用途 | 卡片上的小标记 | **点击筛选游戏列表** |

**为什么不能复用 `tags`**：
- `tags` 在 `GameRecord` 里，是上游 schema（D10）——加「分类管理 UI」会污染那个契约
- 分类需要**自己的生命周期**（重命名、删除时批量解除归属），tag 没有这个概念

### 4.2.1 数据结构

`library-meta.json` 新增两级：

```jsonc
{
  "1": {
    "work": { ... },
    // 这个游戏属于哪些分类（分类 id 数组）
    "categories": ["action", "favorite"],
    "editedFields": [ ... ]
  },
  // 分类定义表（新顶层键）
  "categories": {
    "action":   { "name": "动作类", "order": 1 },
    "favorite": { "name": "我喜欢的", "order": 2 }
  }
}
```

**id 用 slug**（`action` / `favorite`）而不是自增数字：重命名时 id 不变，不用改所有游戏引用。
**`order` 用于侧边栏排序**（用户可拖动调整，第一版先按创建顺序）。

### 4.2.2 关键操作与边界

| 操作 | 行为 |
|---|---|
| 新建分类 | 名字查重（同名拒绝并给提示）；生成唯一 slug |
| 重命名 | **只改 `name`，id 不变** → 所有游戏引用自动跟随 |
| 删除分类 | **只删定义 + 从所有游戏上移除该 id，绝不删游戏**（D31 精神） |
| 把游戏归入分类 | 追加 id（已在其中则跳过）；**支持批量**（U1 的多选直接复用） |
| 「未分类」 | **虚拟分类**，不出现在 `categories` 表里；筛选条件 = `categories` 为空 |

**⚠️ 落盘白名单陷阱**（已知坑，这条必踩）：`library-meta.ts` 的 `sanitize()` 是字段白名单，
新加的 `categories` 不写进去会被**静默丢弃**。改完先看 `saveGameMeta` 的返回键集。

### 4.2.3 UI

```
侧边栏：
  [全部游戏]
  [未分类]                    ← 虚拟分类（快捷入口）
  ─────────────
  [动作类]        [⋯]        ← ⋯ = 重命名 / 删除
  [我喜欢的]      [⋯]
  [+ 新建分类]
```

批量模式（§4.1）的工具栏里加一档：`[设为分类 ▾]` —— 多选一个下拉，勾选要归入的分类
（**多选 checkbox**，符合「多归属」语义）。

## 6. U5：只保留「选择文件」，去掉「选择文件夹」

**用户问「我不确定我这样想得对不对，你可以想一下」→ 本鱼想了，结论：他是对的，但有个例外。**

| 引擎 | 游戏入口 | 选文件能行吗 |
|---|---|---|
| NW.js（MV/MZ） | 目录（`package.json` + `nw.dll`） | ✅ 选目录里的 `package.json` 即可 |
| MKXP-Z（XP/VX/VX Ace） | **目录**（`Game.ini` + `Data/`） | ✅ 选 `Game.ini` 即可 |
| EasyRPG（2000/2003） | **目录**（`RPG_RT.ldb`） | ✅ 选 `RPG_RT.ldb` 即可 |
| Ren'Py | **目录**或 exe | ✅ 选 exe 或 `.py` |

**结论**：`autodetect` 的规则全都是「目录里有哪些文件」，所以**选任何一个标志性文件都能反推目录**。

**→ 可以去掉「选择文件夹」，只留「选择文件」。**

**但有两个例外要注意**：
- **用户可能选错文件**（选了 `readme.txt`）→ 要给出「这个文件不像游戏入口，已把同目录当候选」的提示
- **Ren'Py 的 exe 在子目录**（`游戏名/game/`）→ 选 exe 时反推的是 `game/` 而不是 `游戏名/`，要向上找

## 7. U6：去掉「跳过，稍后安装」+ 识别错了能改

### 7.1 去掉跳过

**现状**：`AddGameWizard.vue:338` 有「跳过，稍后安装」按钮（`wizard.skipInstall`）。

**用户理由**：「感觉没必要」。**本鱼同意** —— 因为引擎没装**游戏根本跑不起来**，
让他跳过等于让他后面必踩一次「点启动失败」。**不如就装**。

**但删按钮 ≠ 强制**：如果下载失败（网络问题），还是要能**把游戏先存下来**，容错路径保留
（只是不把它做成一个显眼的按钮，改成失败后的提示「游戏已保存，引擎可稍后在引擎页安装」）。

### 7.2 识别错了能改

**现状已查实**：`wizard.notDetectedHint` 文案写着「可以从下面的候选里手动选择」
→ **识别成功时没有手动改的入口**，只有「识别失败」才有候选列表。

**修法**：识别成功后也显示一行「引擎：NW.js（自动识别）　[改]」，
点「改」展开候选列表（与失败时的同一个组件）。

## 8. U7：完善信息步骤直接用元数据（**这是最对的一条**）

**用户原话**：「现在的还是好早之前的，好割裂，每次导入游戏之后还要专门编辑进去再查找对应的」

**现状痛点**：
```
添加游戏 → 填标题 → 保存 → 进编辑页 → 找 RJ → 搜索 DLsite → 选 → 保存 → 返回
                                    ↑ 这些本该在添加时就做完
```

**方案**：把「完善信息」这一步重做成**与编辑页同一套组件**：

```
步骤「完善信息」：
  标题（自动从目录名推，可改）
  封面预览（DLsite 封面 / 图标 / 占位）
  ─────────────────────────
  DLsite： [自动识别 RJ] [按名字搜索]  ← 内联，不弹窗
  ─────────────────────────
  分类（新建的，见 U2）
  标签（可选）
  [完成]
```

**关键**：**复用编辑页的组件，不要复制第二份**。编辑页已有的：
- `titleSource` 三态提示
- 封面预览
- DLsite 搜索候选列表
- 字段编辑

→ 应该抽成 `GameInfoForm.vue`（**编辑页与向导共用**）。这是 M5.0 里工作量最大也最有价值的一项。

## 9. U8：编辑页重构（**用户最不满意的一项**）

### 9.1 用户的批评是准确的

原话：「感觉你是每次有新功能都是直接一股脑往后面塞，而没有好好让他们协调一下」。

**现状证据**：`GameEditPage.vue` **1096 行 / 5 个 `<section>`**：

```
1. 基本信息（标题 / 路径 / 引擎）
2. 封面与标签
3. 引擎参数
4. 启动诊断
5. DLsite 信息      ← 塞进来的
```

**问题**：DLsite 信息被当成「附录」塞在最后，但它其实是**游戏身份的主数据**
（标题、封面、社团、发售日都来自它）。

### 9.2 具体痛点（用户点名）

| # | 痛点 |
|---|---|
| a | 「用名字搜索还专门点一下出现一个新的搜索名字的窗口然后再搜索」→ **搜索应该内联在有 RJ 输入框旁边** |
| b | 「保存都还需要 dlsite 信息卡片里面保存一次，整个编辑页面再保存一次」→ **两次保存** |

### 9.3 重构方案

**① 两次保存 → 一次**

现在 DLsite 面板内部有自己的「保存」按钮（因为它走 `saveGameMeta`，而主表单走 `saveGame`）。
**改成：全页只有一个「保存」**，内部把两件事一起提交：

```ts
async function save() {
  await api.saveGame(id, toPlain(draft))
  await api.saveGameMeta(id, { work: toPlain(work), editedFields })
}
```

**为什么原来分两次**：M2.5 加 DLsite 面板时，它独立于主表单，改动不想触发主表单的校验。
但用户体验上**这就是两个按钮做一件事**，必须合并。

**② 区块重排（按「用户实际填表顺序」而不是「功能上线顺序」）**

```
┌─ 游戏身份（DLsite 为主） ────────────────┐
│  封面预览（大图）                         │
│  标题（DLsite 标题 / 手改 / 目录名 三态）  │
│  RJ 号：[输入框] [自动识别] [按名字搜索]   │ ← 内联，不弹窗
│       └ 搜索结果直接展开成候选列表         │
│  社团 / 发售日 / 价格                    │
├─ 本地信息 ─────────────────────────────┤
│  路径（只读 + 打开目录）                  │
│  引擎（下拉 + 改）                        │
│  分类 / 标签                             │
├─ 引擎参数（折叠，高级）──────────────────┤
├─ 启动诊断（折叠）────────────────────────┤
└─ 底部固定：[保存] [取消] ────────────────┘
```

**核心变化**：DLsite 从「最后一块附录」变成**第一块主数据**。

**③ 拆文件**

1096 行拆成：

```
GameEditPage.vue        主容器 + 路由/保存
components/
├── GameIdentitySection.vue   DLsite 为主的身份区（含内联搜索）
├── GameLocalSection.vue      路径/引擎/分类/标签
├── GameEngineArgsSection.vue 折叠的引擎参数
└── GameDiagnosisSection.vue  折叠的诊断（从现页面搬）
```
